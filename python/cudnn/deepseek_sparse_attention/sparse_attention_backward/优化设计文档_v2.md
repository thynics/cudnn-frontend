## 0. 结论

```text
single fused kernel
cluster = (2,1,1)，每 query token 一个 cluster
CTA c 拥有 H64_c = heads [64c, 64c+64)
全部五类 GEMM CtaGroup.TWO（PTXAS 禁止混用 CG1/CG2 MMA）

核心原则（对 v1 的三条反转）：
1. ownership 保持 H-native：Q/dO/P/dS 全程留在生产它们的 CTA，
   不做任何跨维度 re-ownership route。
2. dV/dK 的 H128 归约拆成两个 K=H64 的 CG2 pass 累加进同一 TMEM
   accumulator（= FA4 dkdv 的 GQA-loop 累加模式，2 次迭代）。
3. 大操作数的重定向 = 对不可变源的额外只读（TMA 从 GMEM/L2 重读、
   稀疏 gather 重读），绝不做片上 capture/rewrite/破坏性变换。
   唯一跨 CTA payload：P/dS 各一个 4 KiB off-diagonal 块 / CTA / tile，
   单条 cp.async.bulk.shared::cluster 直发（FA4 fused dS-exchange 模式）。
```

结构收益（相对 baseline 8.517 ms @ S4096/H128/D512/topk2048）：

```text
dKV atomic RMW      : 32 GiB -> 16 GiB，且 pair 内同址争用为零
K 主输入            : 每 tile pair 128 KiB -> 64 KiB（N-split 各 gather 一半）
K stage 回收        : dP 后即回收（baseline 要等 dQ 用完，3/5 tile 更早）
MMA atoms/tile      : 104（baseline 112），S/dP 每 SM 64 行与 baseline 持平，
                      dV/dK/dQ 全部 M=256 全宽
跨 CTA exchange     : 16 KiB/tile/pair bulk DSM（v1: 112 KiB 远程 + ~450 KiB
                      片上重排，全在关键路径）
```

预测（对抗评审的组件模型，含 atomic slot 计数不确定性）：

```text
expected ≈ 4.5–5.0 ms（1.7–1.9x baseline）
worst    ≈ 5.5–6.0 ms（≥1.4x，即使 red.v4 按 4 个标量 slot 计）
best     ≈ 4.0 ms（CONFIG B 生效时可再向 ~3.5 逼近）
```

## 1. Baseline 时间去向（证据链）

- **dKV atomics 是 #1 或并列 #1 瓶颈**。baseline reduce warp 逐 fragment 发
  16B 向量 `red.global`（4×FP32），总计 2.15e9 条指令 / 8.59e9 标量 /
  32 GiB RMW，且同 token 的两个 H64 CTA 并发写**完全相同**的 workspace
  地址。B200 全局 atomic ≈ 512 标量 slot/cycle：若按标量计，仅 atomic
  发射就 ≈ 8.5 ms（与实测 8.517 惊人一致）；若按指令计 ≈ 2.1 ms，外加
  L2 侧 ~64 GiB 的 RMW read+write（~3 ms @ 21 TB/s）。两种读法下都是
  最大可攻击项。
- 主输入 HBM：4352 KiB/token（K 被两个 CTA 重复 gather）≈ 17.4 GiB ≈ 2.2 ms。
- TC busy：S/dP 是 M64-CG1（每 SM 64 行 = 半速），合计 ≈ 3.4 ms
  （全速下界 2.44 ms）。
- 单级 sK：gather(t+1) 只能在 dQ3(t) 释放 K 后启动，稀疏 gather 延迟部分暴露。

## 2. v0/v1 为什么输（反面教材，构成 v2 的硬规则）

- v0（23.44 ms = 2.75x 慢）：640T KiB 主输入放大 + 3×48 KiB 通用 FIFO +
  串行 dV→WAIT_Q→dK→dQ。
- v1 实测 ~10x 慢的真相：跑的是 **V1A0 —— 刻意完全串行化的正确性
  bring-up**（无流水线、无角色分工、每 phase 全 cluster barrier 锁步，
  每 macro ~34 对 cluster arrive/wait + ~7200 条 16B st.async 消息 +
  ~450 KiB 片上 capture/rewrite）。设计文档里的流水线版 v1 从未存在。
  但结构教训独立成立：
  1. 跨维度 re-ownership（K N→D、Q/dO H→D、dS H→N）迫使四条片上
     transpose 路径，其真实成本是 CUDA-core 发射、barrier 延迟与 SMEM
     带宽，不是"字节数"；
  2. 破坏性原位变换迫使 3 个 cluster 往返的 capture 协议；
  3. stage aliasing 链（K_N→K_D→gradA）把下一 tile 的 gather 锁在上一
     tile 最后一个 atomic 之后 —— 预取深度归零；
  4. macro-2 把所有停顿的影响面翻倍。

v2 硬规则：**无原位改写、无破坏性变换、无 macro、每个 buffer 单一生产者。**

## 3. 两条约束性定理（评审产物，划定设计空间）

**T1（RMW 不可消除）**：dKV 行由每 token 的 topk 索引散射，跨 token 冲突
不可避免；没有倒排索引就没有 KV-stationary 零 atomic 方案（FA4 hd256 的
零 atomic 依赖 dense attention 天然可 KV-stationary，不可迁移）。所以只能
**减半 +去争用 + 换发射路径**，赢家是把 drain 藏在最多并发数学后面的方案
——只有融合 kernel 能让五类 GEMM 全程覆盖 drain。

**T2（P/dS 交换下界）**：CG2 的 B 操作数被硬件 N-split（CTA c 必须物理持有
B[N32_c,:]），而 softmax 输出天然 H-split（CTA c 的 TMEM 只有 P[H64_c,N64]）。
任何单 fused all-CG2 kernel 的 dV/dK 都必须搬运两个 off-diagonal
H64×N32 块 × 2 tensors = **16 KiB/tile/pair，恰好是本设计的 DSM 账单**。
不能更少；用 GMEM 往返替代只会更贵。

## 4. Ownership 与数据面（CTA c ∈ {0,1}，peer = 1−c）

记 `Dq(r,c) = D[256r+128c, 256r+128c+128)`（round r 的 CG2 M-split 切片）。

| 数据 | 归属 / 形状 | 来源 | 生命周期 |
|---|---|---|---|
| Q, dO stationary | [H64_c, D512] K-major SW128，各 64 KiB | 每 token 一次 TMA（baseline/v1_load 同款） | 整 token |
| LSE/sumOdO | [H64_c] FP32 | cp.async | 整 token |
| K score stage | [N32_c, D512]，32 KiB，单级 | cp.async gather 本 CTA 的 32 行 | S/dP 用完即回收（gather(i+1) 于 dP(i) 后启动）；loop 结束后 alias 为 dQ epilogue staging |
| round region | 32 KiB = 2×16 KiB 交替 buffer，每 tile 10 个 generation | 见 §6 | 每 generation 一个消费 GEMM |
| P region | 12 KiB = 本地块 [H64_c,N32_0] + [H64_c,N32_1]（各 4 KiB，独立 swizzle 原子块）+ 4 KiB peer landing [H64_peer,N32_c] | stmatrix 本地写两块；peer 块由对方单条 4 KiB bulk DSM 推入 | 单级镜像，dV 全部 pass 用完由 leader 一条 multicast commit 释放 |
| dS region | 同 P 结构，12 KiB | 同上 | dQ（两个 K-chunk 读两个本地块）与 dK 用完释放 |
| sTopkIdx | 64×Int32 | gather warp 写一次 | reduce warp 复用，消灭 GMEM 索引重读 |
| CONFIG B staging | +8 KiB（2×4 KiB ping-pong，独立 buffer，不 alias round region） | reduce warp | 仅 CONFIG B |

## 5. 五类 GEMM（全部 CtaGroup.TWO）

| GEMM | (M, N, K-red) | A（M-split，每 CTA 切片） | B（N-split，每 CTA 切片） | acc |
|---|---|---|---|---|
| S | (H128, N64, D512=32 kblk) | Q stationary [H64_c,D512] K-major | K score [N32_c,D512] K-major | S: 每 CTA [H64_c,N64]（CG2-M128 fold） |
| dP | 同上 | dO stationary | 同一 K stage（V=K） | dP 同 S |
| dQ r∈{0,1} | (D256, H128, N64) | K_dQ gen [N64, Dq(r,c)] MN-major（gather 专用 stage） | dS^T：CTA c 恰好供列 H64_c = **本地 dS 两块原样**（2 个 N32 K-chunk，各自 descriptor base） | dQ r: [Dq(r,c),H128] 128 col，跨 tile 持久累加；两 round 背靠背发射（v1_deep_p 教训） |
| dV (r,h) | (D256, N64, H64) ×2r×2h | Q/dO 象限 gen [H64_h, Dq(r,c)]（TMA 重读，day-1 全部 8 个象限皆流式） | P 块 [H64_h, N32_c]：h=c 本地块，h=peer landing 块 | dKV slot r（64 col）：dV(r,h0) acc=0（每 tile），其余 acc=1 |
| dK (r,h) | 同上 | Q 象限 | dS 块同构 | 同 slot 累加（dV+dK 融合，baseline 同款） |

要点：
- **dQ 的 B 是本地 math 原生产物，零交换**（N-split by H 与 softmax 的
  H-split 天然重合）—— 这是 v2 相对 v1 的第一处结构性省账。
- dV/dK 的 2-pass = FA4 dkdv GQA 循环累加；数值上与 baseline 的 4-panel
  FP32 TMEM 累加同一 reduction-order 类，BF16 量化点不变，5e-2 容差内。
- **CG2 descriptor 单地址规则**（评审 fatal 发现）：一条 CG2 MMA 的
  a-desc 地址在两个 CTA 的 SMEM 空间同偏移解释，且 pass h 时非 h rank
  的 CTA 根本不持有 H64_h 行 —— 所以 stationary 的原位 MN-recast 切片
  **不可用作 dV/dK 的 A**。A 必须进 rank 对称的 slot；day-1 全部经 TMA
  从 GMEM 流式重读（canonical layout by construction，零 descriptor 风险；
  L2 热，+16 GiB L2）。v2.2 优化项：h=c 的象限改为 stationary→slot 的
  16 KiB 本地 bulk 拷贝（byte-identity 已证明：K-major [H64,D512] 的
  [Dq,H64] 切片 = 连续 16384 B 且逐字节等于 canonical MN-major slot
  布局），需先过独立 layout 单测。
- dQ epilogue：每 CTA 每 round 输出 dQ[H128, Dq(r,c)] slab —— T2R →
  BF16 → 死掉的 K stage（32 KiB 恰好一个 slab）→ TMA store。无交换、
  无 atomic（mdQ 已是 [D,H,M] 视图，各 CTA 写不相交 D 列）。

## 6. round region 协议（评审修正后的定稿）

每 tile 10 个 generation 流经 2×16 KiB buffer（A/B 严格交替）：

```text
g1  K_dQ r0     (A, gather 64行×256B)  -> dQ(r0)
g2  K_dQ r1     (B, gather)            -> dQ(r1)
g3  dO[h0, r0]  (A, TMA 16 KiB)        -> dV(r0,h0)
g4  dO[h1, r0]  (B, TMA)               -> dV(r0,h1)
g5  Q [h0, r0]  (A, TMA)               -> dK(r0,h0)
g6  Q [h1, r0]  (B, TMA)               -> dK(r0,h1)
g7  dO[h0, r1]  (A, TMA)               -> dV(r1,h0)
g8  dO[h1, r1]  (B, TMA)               -> dV(r1,h1)
g9  Q [h0, r1]  (A, TMA)               -> dK(r1,h0)
g10 Q [h1, r1]  (B, TMA)               -> dK(r1,h1)
```

- **每个 (generation 类型 × buffer) 一对独立 full/empty mbarrier**
  （评审证明共享 mbarrier 会 parity-skip 腐坏：waiter 无法跳相位）。
  每个 mbarrier 每 tile 恰好翻转一次，parity 干净。
- full 合同：gather generation = 两 CTA elected remote arrive（无 tx）；
  TMA generation = 2 arrives + 16384×2 tx（CG2-group TMA）。
- empty 合同：leader 在该 gen 的消费 GEMM 之后 commit（multicast 到两个
  CTA）。K_dQ 的 empty 释放给**下一 tile** 的 gather。
- 填充源全部不可变（GMEM / topk 行），可无限提前，深度受 2 buffer 限制；
  稳态为吞吐界（~65 GB/s/CTA L2 热读）而非延迟界，预期暴露
  ≤0.1–0.3 µs/tile，已计入 §10 预测。

## 7. P/dS 交换协议（invariant I1，评审定稿）

- math warp 在 T2R+softmax 后：stmatrix 写**本 CTA** P 两块 + dS 两块
  （COL_MAJOR H-contig，baseline 同款 store op）→ fence + barrier(128) →
  elected remote arrive 到 leader 的 P/dS full。
- 同一 acquire 之下（**不加任何额外等待**），elected 线程执行
  `mbarrier_arrive_and_expect_tx(peer dsm_full, 4096)` + 单条
  `cp.async.bulk.shared::cluster`：把本地块 #peer（即 [H64_c, N32_peer]）
  推进 peer 的 landing。FA4 flash_bwd_sm100.py:3287-3298 逐字模式。
- **I1（multicast 代理不变量）**：P 镜像的释放 = leader 在 dV(r1,h1) 后的
  一条 commit **multicast 到两个 CTA** 的 empty —— 所以"本地 P empty 翻转"
  ⇔ "peer 的 landing 已空"。发送方唯一的门 = 它本来就需要的本地
  producer_acquire，一个等待覆盖三个 hazard（本地覆写 / peer landing
  覆写 / 出站 bulk 源覆写——传递闭包：receiver full ⇒ bulk 读完成 ⇒
  dV 发射在其后 ⇒ release 更在其后）。dS 同构（dK(r1,h1) 释放）。
- 每 CTA 一个 **relay warp**（FA4 同款）把 landing 的 complete_tx 转成
  leader 可消费的 2-count arrive —— leader 永不自旋 cluster-scope
  mbarrier（v1 教训）。
- **有界偏移引理**（评审证明）：CTA 要发 tile i+1 的块必须先过
  P/dS(i) 的 release，而 release 依赖双方 tile i 的块已被消费 —— 任何
  CTA 领先 peer 不超过一个 exchange generation，单级 landing 安全。

## 8. 调度（旋转一拍：tile i−1 的梯度藏进 tile i 的 S/dP 阴影）

评审证明同 tile 顺序（S→dP→math→dQ→grads）会把 softmax 链暴露在 TC
关键路径上（~0.5–0.6 µs/tile ≈ +1 ms）。定稿为 FA4 式 interleave 的推广：

```text
稳态一个周期（P ≈ 1.96 µs 理想 / 2.16 期望）：
S(i)                                    [K score(i) 已于上周期 gather]
  || math(i-1..): T2R S(i) 后开始
dV(i-1,r0,h0) dV(i-1,r0,h1)             [P 块 (i-1)：本地 + relay 门]
dK(i-1,r0,h0) dK(i-1,r0,h1) -> slot0 commit -> reduce drain(slot0)
dQ(i-1,r0) dQ(i-1,r1)                   [dS_H(i-1)，K_dQ gens]
dP(i)  -> 释放 K stage -> gather(i+1) 启动（比 baseline 早 3/5 tile）
dV(i-1,r1,*) dK(i-1,r1,*) -> slot1 commit -> drain(slot1)
  || math(i): softmax、stmatrix、双 4 KiB bulk DSM
S(i+1) ...
```

（精确到 µs 的两 tile 事件轨迹、无环证明、以及每个异步操作的
覆盖跨度表在评审记录中已闭合；关键结论：稳态 TC 无暴露间隙，唯一
>0.2 µs 的最坏暴露是 score gather 的 HBM 尾部 ~0.34 µs/tile 上界，
期望为 0，预算 +0.15 ms。）

Warp 计划（16 warps / 512 threads，比 baseline 少 4）：

```text
W0-3  gather：score 行 + K_dQ generations（cp.async；40 reg）
W4-7  math：T2R/softmax/stmatrix + elected 双 bulk DSM + dQ epilogue（128 reg）
W8-11 reduce：dKV drain —— 流量减半后 4 个 warp 足够（128 reg）
W12   MMA leader（40 reg）；follower CTA 的 W12 不执行任何 pipeline 操作
      （FA4 规则，评审指出镜像等待会相位漂移死锁）
W13   load：stationary TMA、stats、全部 round-region TMA 填充（40 reg）
W14   relay（40 reg）    W15 idle
```

## 9. 资源预算（硬上限 232448 B / 512 col）

SMEM（byte-exact，1 KiB 对齐）：

```text
stationary Q + dO                131072
K score stage（后作 dQ staging）  32768
round region（2×16 KiB）          32768
P region（4K+4K 本地 + 4K landing）12288
dS region                         12288
LSE/sumOdO + sTopkIdx               768
mbarriers（~40×8B）+ ctx + pad    ~1800
------------------------------------------------
CONFIG R 合计                   ~223,752  (slack ~8.5 KiB)
CONFIG B 追加 staging             +8192  -> ~231,944 ✓
```

TMEM（alloc 512）：

```text
S 32 + dP 32 + dQ r0 128 + dQ r1 128 + dKV slot0 64 + slot1 64 = 448
（若 CG2-M128 fold 实测 cosize=64：S@0,dP@64,dQ0@128,dQ1@256,
 dKV0@384,dKV1@448 = 512 恰满，两套 map 都成立；实现时以
 make_fragment_C cosize 为准）
无任何 TMEM alias——baseline 的 col-128 alias 与 id7/id8 named barrier
协议整体删除。
```

## 10. 流量与瓶颈总账（每 tile pair 稳态 / 全程）

```text
HBM 唯一           : K gather 64 KiB（全程 ~10 GiB ≈ 1.3 ms，不构成瓶颈）
L2 热重读         : K_dQ 64 KiB + QdO 象限 128 KiB
DSM bulk           : P/dS 16 KiB（T2 下界）
atomic RMW         : 128 KiB FP32（halve），pair 内同址争用为零
                     （跨 token 冲突保留，已计入 16 GiB）
L2 rollup（全程）  : K 12 + K_dQ 4 + QdO 16 + RMW 2×16 ≈ 60 GiB ≈ 2.9 ms
TC busy            : 2.7–3.4 ms（取决于 CG2-M128 实测速率 90%/50%）
atomic 发射 floor  : 1.07 ms（v4=1 slot）… 4.27 ms（v4=4 slot），全程可与
                     TC 流重叠
kernel 级下界      = max(TC, L2, atomic floor) × overlap 效率
```

## 11. dKV drain：CONFIG R（默认）/ CONFIG B（编译期开关）

- **CONFIG R**：T2R → 寄存器 → 16B 向量 `red.global`（v1A0 的
  `_atomic_add_fp32x4` 原语），每 CTA 只 drain 自己的 Dq(*,c) 列。
  代码即 baseline reducer 移植，风险最低；最坏情形（v4 按 4 slot 计）
  atomic floor 4.27 ms 仍可全程隐藏于 TC 流 → wall ≈ 4.6–5.3 ms。
  注意：CG2 M256 的 lane→row 映射（lane m = D row m）与 baseline
  M128-CG1 panel 的列打乱不同——**v2 自带 canonical-order convert kernel**
  （v1 host base 已有 `convert_canonical`），不依赖 baseline 的解扰。
- **CONFIG B**：T2R → SMEM staging（自然行序）→ 每有效行一条 512 B
  `cp.reduce.async.bulk.global...add.f32`（FA4 dQaccum 的机制），绕开
  atomic ALU 计数路径。若 IKET 显示 reduce-bound 再启用。
- 建议（非阻塞）：在 haifa 交互会话跑两个 20 行微基准——red.v4 计
  1 还是 4 个 slot；cp.reduce.bulk 是否绕开 ALU 限制、并发同址是否
  正确累加。可先按 R 上线，用 harness A/B 定夺。

## 12. 尾部与正确性协议（R1–R8，评审定稿）

- **R1**：mbarrier_init 全部 → fence.mbarrier_init → cluster arrive/wait，
  先于任何 producer 活动。两 CTA 从同一 GMEM 标量推导 T，全部循环次数
  是 T 的函数——cluster-uniform by construction。
- **R2**：首个处理 tile（逆序=最后一个 topk tile）：empty 侧全部预释放
  （DSL init / 手工 pipeline 初相=1，FA4 惯用法）；dQ 两 round 仅此 tile
  acc=False；dV(r,h0) **每个 tile** acc=False（slot 逐 tile overwrite）。
- **R3**（partial tile）：两 CTA 用同一份广播索引寄存器算 validity；
  gather 对 score stage 无效行**和两个 K_dQ generation 的无效行**（评审
  fatal 发现：未初始化 SMEM 可编码 Inf/NaN，0×Inf=NaN 会毒化 dQ）显式
  零填充；math 对无效列把 P/dS mask 成精确 BF16 零；reduce 按
  topk_idx<0 谓词跳行。
- **R4**：奇偶 T 无特殊规则——纯 per-tile 调度，dKV slot 按 round 而非
  tile 奇偶。T∈{1,2,3,31,32} 全部退化为 R2+R3+R5。
- **R5**（末 tile）：leader 发 dQdone commit；K stage 死后作 epilogue
  staging；两 CTA 各写两个 [Dq(r,c),H128] slab，不相交。
- **R6**：最后一次 TMA store 与 atomic/bulk 退休后、tcgen05.dealloc 前，
  全 cluster rendezvous（is_two_cta allocator，两 CTA 无条件参与）。
- **R7**（T=0）：uniform 分支：跳过 stationary 与循环，但**两 CTA 仍执行**
  TMEM alloc → 零填充 dQ slab 写出 → R6 rendezvous → dealloc。
- **R8**：有界偏移引理保证任何跨 CTA 单级 buffer 处 skew ≤ 1 generation。

## 13. 备选与回退（评审钢人结论）

| 方案 | 带宽/风险要点 | 判决 |
|---|---|---|
| A：两 kernel 拆分（k1=S/dP/dQ 全CG2 零DSM；k2=CG1-M128 dV/dK 消费者） | P/dS spill 4 GiB workspace @S4096（S8192 翻倍）；两次 launch 串行损失 ~1.5–2.5 ms 重叠；k1 是 v2 的严格子集 | **命名回退**：仅当 fused 流水线闭合失败时启用，数天可上线，3.4–6.9 ms |
| B′：全象限流式（无 stationary 拷贝优化） | = v2 day-1 形态本身 | 已并入 v2 |
| C1：tile-pair N128 macro | TMEM 640>512 或恰满零 slack；奇尾整 tile 浪费；macro 反模式回归 | 否决 |
| C2：D-split stationary | 直接杀死 S/dP（v1 毒药换皮） | 否决 |
| C5：倒排/dense 重算零 atomic | topk2048 密度 50% → dense 重算 ≈6.3–6.6 ms 平底 | 仅当 atomic 世界最坏且需确定性时再议 |
