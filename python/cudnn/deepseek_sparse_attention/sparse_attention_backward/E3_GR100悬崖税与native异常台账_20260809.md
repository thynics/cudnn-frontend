# E3 战役台账：GR100 上 rubin_native 异常与 baseline 差距拉大的归因（2026-08-09，8-10 终审闭合）

**两个母问题**（本台账的存在理由，防跑偏锚点）：
- **Q1**：为什么 final 家族与 baseline 的差距在 GR100 上进一步拉大（B200 1.14× → GR100 1.5-1.6×）？
- **Q2**：为什么 rubin_1 native（环5/双面/oversized）在 GR100 上异常地慢（13.3ms = 3.0× baseline，
  比 final 原样还慢 77%）？

**归因进度：Q1、Q2 全部闭合（E3STR r8 三臂 NCU，2026-08-10）。**

## 0. 终审判决（E3STR r8，lc-0328/Slurm 3559155，revision cda5cc0）

**native 灾难 = 单一机制两剂量：局部内存（spill/栈）流量 × 8KB-L1 饥饿。**

三臂同 job 同节点 @topk512，主 kernel 同名、6 实例、96 regs/thread（三臂全同）：

| 指标 | compat | e3pad | native | n/e3pad |
|---|---:|---:|---:|---:|
| duration (ms) | 2.407 | 3.010 | 4.371 | **1.452** |
| **STL 指令** | 35,692,544 | **35,692,544（逐位同）** | **52,502,528** | **1.471** |
| LDL 指令 | 56.85M | 65.61M | 101.32M | 1.544 |
| local miss% | 48.39 | 85.77 | **91.08** | — |
| L2 局部读 | 3.42GB | 6.09GB | **8.78GB** | 1.44 |
| SMEM wavefronts ld/st | — | 基准 | ×1.10 / ×0.92 | 平 |
| bank conflicts st | — | 基准 | **×0.60** | 降 |

- **剂量一（悬崖税 +1.28µs/tile，E3-240+E3NCU r3 判 l1_class）**：家族固有 ~12.8GB/launch
  局部流量失去 L1（48→86% miss）；悬崖复查在 r8 逐位复现（1.250/1.784/+37.4pp）。
- **剂量二（结构残差 +3.91µs/tile，E3STR r8 判 spill_amplification）**：环5/双面代码在
  同一 96-reg 天花板下**静态多溢出 47%**（STL 指令 ×1.471 = 代码级铁证；两 ring2 臂
  STL 逐位相同 = 同码对照），miss 再升至 91.1%；LDL 超额部分（×1.544>×1.471）
  为自旋等待重载的动态回声。
- **S3（>256KB 寻址）证伪**：SMEM wavefronts/bank 全部平坦（bank st 反而降）；
  E7 字段重排腿取消。S2（臂串行化）仅下游回声（barrier ×1.165）。
- 数量闭合：native−e3pad 额外 L2 局部流量 ≈4.9GB/launch，Little's law 粗账
  ≈+4.9M cycles vs 实测 +3.27M cycles，1.5× 内吻合。

**修复方向唯一化：despill**（寄存器/角色重构，削减 local 流量）——它同时攻击两个
剂量，且对 compat（48% miss，3.4GB/launch）与 B200（28KB L1，见 C5）都有收益。
容量路线的存亡 = despill 的可行性。

## 0.5 修复线战果（K1a，2026-08-10，k1 r5 = lc-0328/Slurm 3566234，rev 98a05e6）

e3sass r1（SourceCounters 站点图，R_stl=1.471 与 r8 逐位互证）定位三大 spill 桶：
① producer 警队（W16-19，48 regs）等待环自旋状态——单一溢出槽每 launch 重载
60M+ 次；② math 发布路径 local-to-local 数组拷贝（双面视图下）；③ drain 的
REDG 邻居重载。**K1a**（`DSA_RUBIN1_REG_K1A=1`）打①：W16-19 48→64 regs，
资金 = reduce 128→120（动态池恒 61,440 = 640×96）。

四臂同 job 判决（稳态 µs/tile，correctness dq=0/dkv=0.00195 全过，漂移≤0.11%）：

| 臂 | 周期 | Δ |
|---|---:|---:|
| cb (compat 基线) | 4.5977 | — |
| ck (compat+K1a) | **4.1445** | **−0.453 (−9.9%)** |
| nb (native 基线) | 9.7782 | — |
| nk (native+K1a) | **4.4695** | **−5.309 (−54.3%)** |

- **结构残差 +3.91 → +0.33（−94%）**：producer 警队寄存器饥饿正是环5/双面
  活状态的溢出载体，一个 16-reg 旋钮收回全部结构灾难；
- 墙时 topk2048：ck 5.936ms（**1.33× baseline，CG2 家族 GR100 历史最好**）、
  nk 6.568ms（1.47×，从 3.00× 回收）；
- 残余 nk−ck=+0.33 ≈ despill 后缩小的局部流量上的悬崖税（待 K1-NCU 复测证实）；
- 执行链附记：k1 r1-r4 的四连 SSH 失败根因 = `computelab` 别名未命中 SSH 配置
  被裸 DNS 解析到错误 IP（10.127.17.182）；已修（别名+`ssh -G` fail-closed 硬门）。

**K1-NCU 四臂复测已判（r1，lc-0328/Slurm 3566894，rev 4f683ca）**：
- **Q-A 确认**（0.538≤0.60）：ck 局部流量 ×0.538（ld 219.6→124.7M、st
  178.0→89.3M sectors），miss 48.4→36.6%，主 kernel 2.405→1.997ms；
- **Q-B 账目闭合**：nk−ck Δ=+0.337ms ↔ L2 局部读差 +2.24GB/launch
  （nk miss 80.7%@8KB-L1 vs ck 36.6%@108KB）——残余结构差 = 剩余 spill×悬崖税，
  无悬空项；nk 局部流量比 ck 仅 +15%（K1a 前 +37%）；
- **Q-C：ck pacer 仍为 long_sb 19.6**（仅 −11%），barrier 降至 9.8——协议环
  未接管，内存延迟仍主导；ck 残余局部流量 6.9GB/launch（1.46GB 走 L2），
  K 系列仍有肉。K2 靶点（②math 发布拷贝 vs ③drain REDG 重载）需要 K1a 后的
  新站点图——旧 e3sass 图是 48/128 布局，版图已重排。
**e3sassk1 r1 已判（K1a 后站点图，lc-0328/3567171，rev 1ed234e）**：
- K1a 生效双证：K1SASS_ENV 行 + compat stl_executed 71.4M→39.1M（×0.547，
  与 K1-NCU 的 sector ×0.538 交叉互证）；R_stl 1.47→1.18（预登记成功信号）；
- **K2 靶点定形：mbarrier 自旋环溢出指针病**。ck 头号站点 = reduce 警队
  `dkv_done[0]` 等待环的 `LDL [R1+0x108]`（45.5M 次/launch = ck 全部 LDL 的
  ~48%）；同病灶家族（各 mbar 等待环逐圈重载同一栈槽）占预 K1a LDL 的 60%
  （141M/235M）。**K2a（还 reduce 寄存器）出局**：128 regs 时代同环已 48.5M
  次——非 K1a 的 −8 所致，是 PTXAS 循环内溢出病理；
- 关键机理：编译器有 uniform 快路径（`USYNCS...TRYWAIT UP0,[UR12+0x80]`，
  指针在 UR、零 LDL），首次失败才落 LDL 慢环——指针在 UR46 里却每圈从栈重载。
**K2 方案（uniform 预自旋）**：热等待点前插手工 `_mbarrier_try_wait` uniform
循环等到位，再调原 consumer_wait（必走快路径），慢环永不执行、协议语义不变。
前置：dslsrc recon 腿取 runner venv 的 pipeline 源码（mbar 布局/phase 约定，
铁律：协议手术前必读源码）。

**K2 已判：k2_neutral 双臂（k2 r2，lc-0328/3567839，rev 647aa3f）**：
ck2−ck = −0.0044（噪声）、nk2−nk = −0.0224（带内）；correctness 全过；
ck 三轮逐位复现 4.1445（测量机器稳定性锚点）。**物理解释**：自旋重载槽在
ck 命中 108KB L1（重载≈免费），自旋警队本就空转——LDL 流量真实但不在
关键路径。**教训（K 系列定靶纪律修正）：执行计数排名 ≠ 时间排名，
定靶必须用 stall 采样列（时间加权）**。K2 留树、旋钮默认关。

## 2. 已闭合结论（附回执）

### C1（Q1 答案）：吞吐机/延迟机二分
baseline 每 tile 时间全部由吞吐资源承载（发射/张量核/L2 原子/带宽），GR100 的
提升恰好全是吞吐（SM 数 ×1.46、频率 ×1.29、per-SM-per-clock 张量核不变）→
baseline 干净 ×1.8。final 家族的定速项是协议延迟（信用环/DSM/组播），不随吞吐
缩放，且 GR100 上环 cycles 反而 +~46%（互联更远/216 SM）→ 差距必然拉大。
回执：终审对账表（B200 4.71 vs 7.12 分解）+ GR100 波次/频率分解。

### C2：Rubin SMEM 供给是悬崖（硬件事实，硅证）
- 物理 L1+SMEM 合并阵列 336KB；SMEM >228KB 只有 328KB 一档（oversized 新
  属性+launch mode，R-394），**L1 只剩 8KB**，无中间档（308 实验不存在）。
- legacy CUDA API 谎报 232,448/233,472（R-394 兼容要求）；**NCU launch metric
  报真值**：e3ncu r3 实测 carveout compat 233,472 vs e3pad **335,872B**。
- `dynamic_smem` 227,328/243,712 = E3PAD 死填充生效的每臂铁证。

### C3（Q2 之 25%）：悬崖税 +1.2777µs/tile，实质 l1_class
- E3-240（e3pair，lc-0328/3557431）：同协议同活字节布局只切模式，
  compat 4.5968 → e3pad 5.8745；配对质量：两臂 baseline 漂移 ≤0.071%。
- E3-NCU r3（lc-0227/3558106）：预登记门按协议记 unexplained_infra
  （R_local_l2=1.78 < 2），**本地深挖推翻为 l1_class**——门槛校准错误
  （比值门隐含 compat 基线 miss 小，实际已 48.4%）。证据：
  - 本 kernel **重度 spill**：局部读 ~220M sectors（7.0GB）+ 写 178.7M
    （5.7GB）/launch ≈ 107KB读+87KB写/CTA/tile；LDL 5,683 万条；
    96 regs/thread 静态分配，stack 1KB/thread；
  - L1 8KB 下 miss 48.4%→85.8%，**额外 L2 局部读 2.67GB/launch**；
    lg_throttle ×5.15、long_scoreboard ×1.29、barrier ×1.33；
  - **主 kernel Δ+0.592ms 与 e3pair topk512 wall Δ+0.594ms 逐 µs 闭合**
    ——税全部住在主 kernel 内。

### C4：banking / 工具链 无罪（证伪清单）
- bank conflicts 0.99-1.03、SMEM wavefronts 0.995-1.008：oversized 阵列配置
  不改共享内存路径行为。
- 工具链反向：compat@sm_107a/13.4 = 6.756ms **快于** JIT/26.06 口径 7.856ms
  （−14%）；native 的 13.32 是在更好工具链上跑出的——结构问题坐实。
- r2 的 CARVEOUT_ANOMALY 无效：观测对象是 build_case 参考机器的 nvjet TNT
  GEMM（launch-skip 从进程起点计数未及 DSA kernel），非 metric 谎报。

### C5（追溯洞察，待验证）：B200 也一直在付 spill 税
B200 final 运行在 256−228=**28KB L1**，同一个重度 spill kernel 的 miss 率
应介于 48%（108KB）与 86%（8KB）之间——**B200 的 period 里本就含未建模的
局部内存暴露**。despill 手术对 B200/compat/native 三者皆有收益（compat 自己
就在付 48% miss、3.4GB/launch 的账）。可用一发 B200 NCU 便宜验证。

## 3. 未决问题（Q2 之 75%）：结构残差 +3.91µs/tile 归因

native(9.78) − e3pad(5.87) = +3.91，即**同为 oversized 模式下，环5/双面结构
本身带来的恶化**。三个候选（先验排序）：

| # | 假说 | 机制 | 判别信号（NCU 可测） |
|---|---|---|---|
| S1 | **spill 放大**：环5/双面臂增加活指针/相位状态 → 寄存器压力 → spill 体积更大，且每条 spill 在 8KB L1 下 ~4× 贵 | 结构×模式交互 | native 局部 sectors ≥1.3× e3pad；regs/thread 变化 |
| S2 | **新臂串行化**：mod-5 槽序/逐槽相位/双面门从未有性能履历，可能正确但过保守 | 纯协议 | barrier/等待类 stall 显著高于 e3pad，局部流量却接近 |
| S3 | **>256KB 寻址**：第二 P/dS 面落在 269-298KB，描述符/寻址新路径慢 | 模式×布局 | SMEM 路径指标劣化，或 trace 中奇偶 tile 交替签名 |

**判别腿 = 三臂 NCU（compat/e3pad/native 同 job 同节点）**：native−e3pad 差分
在计数器层面直接分家 S1/S2/S3。S3 若 NCU 不可分辨，后续用 E7（struct 字段
重排，零协议改动）与 E5（trace 孪生看奇偶签名）补刀。

## 3.5 执行链战役记录（e3str r1-r8，供后续腿复用）

8 轮中 7 轮为执行链失败，逐个歼灭并固化为合同脚本/kit 约束：
① NGC PATH ncu 2026.2.1 不识 GR100（→ 芯片验证候选遍历 + pin 已验证二进制
`cuda-38248128/ncu`，注意在 toolkit 根目录非 bin/）；② internal toolkit 未挂进
容器（→ `-v /home/scratch.svc_compute_arch:...:ro` 硬约束 + 容器内自证）；
③ 镜像未 fetch 即解析短 SHA（→ 全长 SHA + 显式 fetch 步骤）；④ runner 自写
awk 核验转义炸（→ `sha256sum --check --strict` 原样 heredoc）；⑤ `docker run`
无 `-i` 却经 stdin 传脚本，容器静默退出（→ 容器载荷落盘文件执行）；⑥ 探针
stderr 被 2>/dev/null 丢弃（→ 双流落盘 + 一次带日志重试）；⑦ **pipefail 下
`awk|grep -q` SIGPIPE(141)**——match 在 4k 行输出的第 100 行，grep 提前退出
杀死写端（→ 无管道单进程 awk；元教训：本地验证必须用 kit 自身 shell 选项
`set -Eeuo pipefail` + 真实规模数据，2 行 stub 测不出 SIGPIPE）。
最终形态：两个合同脚本逐字节由发起方提供（SHA 即合同），proxy 只做
scp + stage + 单条 crun + 回传。

## 4. 教训沉淀

1. **比值门要配绝对量门**：R_local_l2≥2 因 compat 基线 miss 已 48% 而失效；
   miss_pct 差分门（≥20pp）才是对的那半。
2. **NCU launch-skip 从进程起点计数**：case 构建的 torch/cuBLAS launch 会吃掉
   窗口；必须 NVTX 门控（`--nvtx --nvtx-include "dsa_bwd/"`）。
3. **live `--csv` 不打 metric 表**：必须 `ncu --import --csv --page raw` 读回
   宽表（首行列名+次行单位；"Kbyte"=十进制千）。
4. **效度硬门**：主 kernel 若为 `void at::*`/`nvjet*` 拒判（r2 失败模式免疫）。
5. **宿主 wrapper**：所有 bind 源目录必须 docker run 前以用户身份预建
   （scratch 为 root-squash NFS，dockerd 代建必死）；crun 只接单脚本路径。
6. NCU 伪影：oversized 配置下 occupancy 族 metric 报 0/inf，非真实差异。

## 三件新武器（全部入库）

### 结论（推翻先前预设）
- "2 CTA/SM 占用不足"论被否决：baseline 同为 1 block/SM 20 warps 就到 22.6%。
- 差距的两条真根：**① CG2 跨 CTA 协议税**（barrier 8×+环自旋）；**② 每线程
  工作集超寄存器**（spill 22×）。两者都源于 2-CTA 工作分解本身。
- 重构问题重述：**CG2 双 CTA UMMA 的 GEMM 吞吐增益，是否值回协议+spill 成本？**
  选项重排：① 单 CTA 变体（baseline 形态 + 我们的调度优化，警惕"CG2 是底线"
  记忆源自 SM100 语境，GR100 335KB SMEM 下值得重测）；② 协议瘦身版 CG2
  （保双 CTA UMMA，砍环代际与栅栏）；③ despill 二期（重排每线程工作集）。
- 至此战役数据链闭卷：九轴判决 + m51/baseline 双画像 + role 时间线 + SASS
  归因俱全。冠军 m51=4.0877（1.310×，总改善 2.39×）。
