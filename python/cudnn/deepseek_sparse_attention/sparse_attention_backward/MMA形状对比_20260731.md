# Baseline (CG1) vs v12 (CG2) 五 MMA 形状对比（2026-07-31）

**动机**：解释两个表面矛盾——① v12 SMEM 占用超过 baseline；② v12 的 dVdK 要流式供应
的操作数远多于 baseline。3-agent 工作流（baseline 提取 + v12 提取 + xhigh 对抗校验；
v12 提取 agent 死于 API 断连，校验员从源码直接重提取补齐）。全部数字带 file:line。

---

## 一、统一判据（本报告最重要的一句话）

**每条 GEMM 的供应成本由"收缩轴是否恰好是所有权切分轴"决定。**
Baseline 单 CTA 什么都不切 → 五条 GEMM 的所有操作数全部零拷贝就地消费。
v12 把 h 轴切给两个 CTA（stationary Q/dO 各持 h-half）、把 kv 轴切给 score staging：
- S/dP 收缩 **D**（未切分）→ 免费 ✓
- dV/dK 收缩 **h**（正是切分轴）→ 每 pass 的 [D×h-half] slab 总有一半字节在对端 → 必须重演 ✗
- dQ 收缩 **kv**（score_kv 已按 kv 切半）→ 必须 kdq 重 gather ✗

## 二、五 MMA 对照表（按 64h×64kv 单位工作归一）

注：DSA 中 K=V 同源（baseline sV=sK 别名 :822），dV+dK 在 TMEM 中合法求和为 dKV。

| MMA | baseline (M,N,K)，atom | baseline A / B（驻留类，B/tile） | v12 (M,N,K) | v12 A / B（驻留类，B/tile） |
|---|---|---|---|---|
| S | (64,64,512) | A=Q 驻留 K-major（0）/ B=K gather 流式 **65,536** | (128,64,128)×4 chunk CG2 | A=stationary Q M-split（0）/ B=score_kv N-split 流式 **32,768** |
| dP | (64,64,512) | A=dO 驻留（0）/ B=sV≡sK 别名（**0 额外**） | 同上 | A=stationary dO / B=同 score_kv（0 额外） |
| dV | **(128,64,64)×4 D-panel**，M=D | **A=dO^T 零拷贝 recast_ptr 视图**（:841，MN-major，**0**）/ B=P 片上 8,192 | (256,64,64) CG2，2 round×2 h-pass | **A=dO^T 象限经 round 环重演 4×16,384**（2 TMA + 2 own-half bulk）/ B=P blocks 4,096+4,096 DSM |
| dK | (128,64,64)×4，M=D | **A=Q^T 零拷贝视图**（:838，**0**）/ B=dS 片上 8,192；dKV 原子 **131,072** | 同 dV，acc=True | **A=Q^T 象限重演 4×16,384** / B=dS blocks；rank-owned drain 原子 **65,536** |
| dQ | (128,64,64)×4，M=D | **A=K 复用 S 阶段的 sK 视图（sK_2 :844，0 额外，:1628 统一释放）** / B=dS^T 视图（0） | (256,128,64) CG2，2 round | **A=kdq K^T 重 gather 2×16,384**（g0/g1）/ B=ds_image 片上 8,192 |

**关键读法**：两边 dV/dK 的 orientation 完全相同（都是 M=D 转置形态、大 panel 都在
A 槽、MN-major）。变化的从来不是"操作数是谁"或"数量"，而是**同一批字节的获取成本：
baseline = 0（recast_ptr 零拷贝视图直吃驻留缓冲），v12 = 128KB/tile 重演**。

## 三、矛盾①：SMEM 账（214,528 → 231,424，Δ+16.9KB）

| 分项 | Δ |
|---|---:|
| round 环（2×16,384，baseline 无此物） | **+32,768** |
| P/dS 协议面（blocks+xchg+landing+image 32,768 vs baseline sP+sdS 16,384） | **+16,384** |
| score-KV 驻留减半（32,768 vs 65,536，真红利） | **−32,768** |
| 净 | **+16,384** |

Baseline 只用 214.5KB 是因为梯度段除 16KB 片上 P/dS 外**零 staging**；
v12 的超出全部是"cluster 计算 × CTA 本地存储"的协议面，不是数据变多。

## 四、矛盾②：dVdK 操作数——被迫且 orientation 无关（校验员判词）

我方原假设"CG2 M-split 迫使转置、转置迫使重演"**被证伪**：baseline 本来就是 M=D。
真正的强迫对 = **h-split 驻留 × CG2 共享描述符**：
1. dV/dK 的 K 维是 h；每个 h-pass 的 [D128×H64] slab 恰好只属于一个 CTA 的
   stationary → 每 gen 必有一个 rank 缺字节（4×16KB GMEM TMA）；
2. 连拥有方也不能就地用：CG2 描述符两 CTA 同址，而 own 字节在 stationary 里的偏移
   是 rank 相关的 → own-half 是 stationary 的**字节恒等切片**（:13601 注释+host assert）
   却仍要 bulk copy 进 rank 对称 round 槽（4×16KB S2S）——这是"重演是协议税"的铁证。
3. **反事实（M=kv=64 orientation）同样逃不掉**：重演字节 orientation 不变
   （2 pass×2 tensor×32,768 = 131,072B/CTA/tile 恒等）；且 TMEM 需 576-640 > 512 列。
   M=D 是自由变量中的严格占优选：TMEM 恰好 512 打满 + dKV 输出天然 rank-owned
   （原子减半、零同址争用）。
4. 唯一逃逸 = h 复制 stationary（+131,072B/CTA → ~304KB > 232,448 cap）——SMEM 封死。

## 五、cluster 级字节总账（校验员核对）

- KV 读（L2 级，每 64h×64k）：baseline 65,536（两 head-CTA 重复 gather，DRAM 靠 L2 吸收）
  = v12 65,536（score 32,768 + kdq 32,768）——**score 减半红利被 kdq 重 gather 精确抵消**。
- 梯度 A 操作数：baseline **0** → v12 **98,304**（HBM/L2 TMA）+ 32,768（own bulk S2S）/CTA/tile。
- dKV 原子：131,072 → 65,536（**被漏记的第二真红利**，rank-owned D-split drain）。
- 与 pacer 账闭环：赢项（score 减半+原子减半+发射合并）−1.7µs/tile；
  重演机器（接力 gap 3.03 + 头 0.77 + 尾 0.68）+4.5；净 +2.4。

## 六、baseline 的 TMEM 戏法（对照参考）

Baseline 靠 192 列别名装下 dKV：4 个 [128×64] panel 只占 3 个槽（p1/p3 分时共享
[128,192)，named barrier 关门 :1650/:2166），S/dP 靠 lane 半区共享 [0,64)，dQ 256 列
跨 tile 持久。v12 则是 512/512 精确打满（S/dP 128 + dQ 256 + dKV 128）。
两边都没有 TMEM 富余——这也是 TMEM offloading 死刑的根据。
