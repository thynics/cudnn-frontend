## 2. 修正后的收益账（以 perf-model 为准，该维度经复核 8/8 findings CONFIRMED）

**排队模型标定**：s = max(b, exec, L_ring/k_eff)，标定误差 0.8%（预测 0.45 vs 实测间距 mean 0.454/median 0.448, n=28）。段值直测：b=0.042 / A=0.163（22/24 样本恰 0.160，近常数 ⇒ A=exec+mc，完成驱动释放实锤）/ C=0.083 / D=0.127 / E=0.089。延迟提交格使现行 k_eff=1（final.py:2423 acquire(g) 先于 :2516-2531 commit(g−1)，探针 ACQ(q+1) 先于 WAIT(q) 直证）。

| 分项 | 方案宣称 | 修正区间 | 修正依据 |
|---|---|---|---|
| 刀①@深度2 | −1.2~−1.5 | **≈0±0.2**（区间 −0.4~+0.4，逐 gen 错峰释放最优变体 −0.3~−0.4） | 前提(i)「A 每圈固定」被 A=exec+mc 常数杀死——exec 随并趟翻倍不摊薄；前提(ii) D 不变被环粒度粗化杀死（32KB/圈÷32KB 环=深度1，D 0.127→0.5-0.6） |
| 刀②@深度3 | −1.1 | **−1.10~−1.81（中心 −1.54）** | 数字巧合近似对（两误差相消）：机制非「D 整段消失」而是收敛到 s=(L_nf+flight)/3≈0.26；但字节+相位双阻塞，不可实施 |

| 使能项 standalone | 未单列 | **−0.4~−0.5**（enabler 维度模型上探 −0.8~−1.1，未实测，作校准假设） | k=2 拆格：s 0.454→~0.39；零字节成本；与②理论可叠但叠加后仍收敛 s≈L/3 无额外收益 |

**period 落点**：
- 字节现实下（②死，仅使能项）：**~6.6-6.7**。
- ②奇迹出资 + 使能项：**5.3-6.0，中心 5.5-5.6**（方案宣称 5.0-5.3 不成立）。
- 全宇宙最乐观（②全兑现 + 未验证头部灌注 −0.2~0.4 全给）：**4.9-5.2**。

**能否 ≤4.6：明确不能。** 三重物理封顶：(a) 供应环在 k=3 下有 ~2.1µs 残余地板；(b) 完全遮蔽需 4-8 槽 = +32~93KB，SMEM 上不存在；(c) 头部灌注 0.77 + 尾波 0.68 = 1.45µs（占追平所需 Δ2.52 的 58%）与环深度/圈数正交，两刀零触及——①反而使头尾各恶化 ~0.1。极端角点 4.6-4.8 的三前提（整链遮蔽/双lane完美/16KB到位）逐一被拒。**维持并加固终审「架构级不可修复」判词：≤+16KB 预算内任何 (k, 粒度) 组合下界 ~5.2-5.3。**

## 3. 单点故障与阻塞项（按严重度）

1. **[blocker] 刀② 16KB 无来源**：SharedStorageV2 精算 230,912B / slack 1,536B（final.py:995-1059, cap :108）；唯一死字段 ds_xchg 4,096B（:1050，kernel 零引用）；合计 5,632B < 16,384B，缺口 10,752B。stationary 128KB（S/dP A 操作数 + own-half DSM bulk 源，驻留到 flat_gen=7）、score_kv 32KB（S/dP B + s_dq_epi 别名 :1366-1373）、ds_image/ds_blocks（K-major vs MN-major 异 swizzle :285-295）全部证死。对抗复核主动猎字节未找到任何隐藏 donor。
2. **[blocker] 刀② 相位旋转**：10 gen/tile mod 3 ≠ 0，gen→buf 绑定是 flat_gen%2 的 const_expr（:2419-2422）+ 静态 fragment 视图（:1374-1393/:1596-1600），主循环动态 cutlass.range（:2403）——深度3 需 12-gen 哑填充/3-tile 展开/动态描述符，各有协议成本或 DSL 高危。
3. **[blocker] 刀① lockstep**：深度2 下配对消费持有全部两槽，供应零预填窗；−1.2~1.5 仅在 ≥深度3-4（+16~32KB）成立，字节双重不可行。v15 红队 Fatal② 判决在急切提交变体下自然延拓，维持有效。
4. **[blocker] W17 内双 lane 形态出局（CONFIRMED）**：本地 DSL 源码直证——`CuTeDSL/cutlass/cute/nvgpu/cpasync/copy.py:155-199` 明文 TMA copy 隐式包 elect_one；`arch/elect.py:147` elect_one = nvvm.elect_sync()（NVVM 无掩码操作数、硬编码全 warp 掩码）。W17 的 4 处 cute.copy（final.py:2442/2463/2485/2506）在 lane 发散分支下执行 = UB/悬挂。落地形态钦定 **W19 空 warp 提交引擎**（warp19 确认空闲，分支链 :2182/2351/2543 直落 :2621；relay 单 lane 先例 :2544-2619；PipelineAsyncUmma producer_commit per-thread 无线程身份耦合，DSL pipeline/sm100.py:318-513 证实；kdq 两 gen commit 留 W17，kdq_barrier count=160 :971-974 不变）。
5. **[blocker] 死锁格（若做①）**：深度2+配对+滞后提交 = tile0 首对确定性死锁（commit(g1)←acquire(g2)←release(g0)←pass(g0,g1)←commit(g1)）；急切提交是①@深度2 的正确性硬需求。深度3 下滞后提交格良基无环——②根本不需要使能项。
6. **[major] stage-0 G2 门**：寄存器分配器非单调（rev3 W17 +2STL / rev4 +10LDL / W16 56干净64劣化先例），任何 W17/W19 改动必须过 allinone 编译期门（W16/W17 [0,0] 硬门 + 新条款 W19 循环体零 STL/LDL），零 GPU 成本、先于任何 B200 run，历史基率预期 1-2 轮 STOP。
7. **[major] probe 能力缺口**:final.py trace-free（仅 1 处死代码 _iket :948-949），v15 IKET 28/29 仅 1 空名额；验证需 ≥2 新 span → 必须建 vm6probe 孪生文件（独立 29 名预算）+ 本地 G5 门（静态名 grep，含 else 分支字符串口径）。

## 5. 方案原文错误（逐条）

1. **「两刀共享 W17 双 lane 使能项」**——三重错：(a) 使能项对刀①@深度2 是正确性必需，对刀②是完全不需要（深度3 滞后提交格良基无环，构造性证明成立）；(b)「W17 内双 lane」形态本身非法（cute.copy 隐式 elect_one，DSL 源码 CONFIRMED）；(c) 依赖方向反了——②是①的前提，非①主②补。
2. **刀① −1.2~1.5 的摊薄机制**——「A 段每圈固定、圈数减半摊薄」把 exec 计入摊薄：A=0.163 近常数 = exec+mc（22/24 样本恰 0.160），8 个 dVdK GEMM 无论并趟与否必须真实执行且串行过张量管，exec 总量 0.8µs/tile 恒定，仅组播分量 ~0.07-0.09 可摊。
3. **刀①未计环粒度粗化**——32KB/圈 ÷ 32KB 环 = 圈级深度1，D 从 0.127 恶化到 0.5-0.6（3-4 倍）而非不变；方案完全没有 pair-depth 概念，其收益隐含 +32KB（管线化）而未申报字节。
4. **刀②「D 段整段消失」**——机制错误：k=3 收敛 s≈0.26，D 部分重暴露；−1.1 是「漏算 A/C/E 摊薄」与「漏算 D 重暴露」两误差相消的巧合，修正 −1.10~−1.81。
5. **「②在并趟后仅 −0.55」**——方向写反：真实是①在深度2 下 ≈0，组合反协同比②单独差 ~1.0~1.4µs。
6. **「常规叠满 period≈5.0-5.3」**——修正 5.3-6.0（中心 5.5-5.6），且以②出资为前提；字节现实下仅 ~6.6-6.7。
7. **极端角点 4.6-4.8 三前提全灭**——「整链遮蔽」需 4-8 槽（+32~93KB）；「双lane完美」只拆格不给深度；「16KB到位」被字节审计证伪（缺口 10,752B）。角点作废，追平线 ≤4.6 在两刀框架内不可达。
8. **台账「深度3 待 L2X 还字节」预期错误**——L2X 字节净零（pds_stage 8,192B 恰由 p_xchg+死 ds_xchg 出资，v15.py:11623-11697），且 L2X=1 反而锁死唯一死字段回收；字节优先路径是 P4-only（L2X=0，+4,096B）。
9. **刀②的 +16KB 口径低估组合需求**——①管线化本身 +32KB，①+② 需 3×32KB 槽 = 相对现状 +65,536B；「+16KB 是 kill list 深度3 死因」的重开审计结论：死因维持。
10. **v15 红队 Fatal②（lockstep）零回应**——终审报告 L84 复活刀①时对该判决只字未提（grep 'lockstep|Fatal|死锁' 全文零命中），本轮确认该判决在急切提交变体下依然有效。
