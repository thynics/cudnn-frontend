# 2-CTA Design v1：SM100 DSA GQA128 / D512 Backward

> 状态：v1 设计规格，尚未实现。本文完成了数学、ownership、逻辑流量、
> 资源 envelope 和抽象依赖 DAG 的静态闭合；CuTe layout lowering、
> PTXAS、寄存器、死锁、实际流量和性能仍是实现前后的硬验收项。  
> v0 的事实规格仍由 [`优化设计文档.md`](优化设计文档.md) 与
> [`优化流水线设计文档.md`](优化流水线设计文档.md) 维护；本文不把 v1
> 候选改写成 v0 事实。

## 0. 结论

v1 固定为：

```text
single fused kernel
native N64
cluster size = 2

S   : CTA.two
dP  : CTA.two
dV  : CTA.two
dK  : CTA.two
dQ  : CTA.two

Q/dO : query-stationary，非空 query 只从 GMEM 读取一次
K    : 每个 issued N64 tile 只从 GMEM 读取一次
P    : 从 math registers 直接发布到唯一 N-owner image
dS   : 唯一 H-owner image，dQ last-use 后原位变成 N-owner image

macro width = 2 logical N64 tiles
Q/dO D-owner materialization = once per macro, not once per tile
```

这条路线保留 v0 的核心，而不是重新发明一个 backward：

- 五类 Tensor Core 数学、native N64、单 kernel 和 2-CTA cluster 不变；
- `load / mma / math / reduce` role specialization 不变；
- `SDP(next) || MATH(current)` 的 overlap 不变；
- dKV 在 T2R 后立即释放 TMEM，atomic 与后续工作 overlap；
- dQ 仍为 D-partition persistent accumulator；
- dV/dK 仍在 cluster 内完成 H128 reduction，因此 dKV atomic 保持 v0 的
  1/2 baseline 数量；
- 只重做 operand residence、ownership route 和两 tile 调度。

相对 v0，v1 的主输入 GMEM 流量从：

```text
L_v0(T) = 640T KiB
```

降到信息下界：

```text
L_v1(T) = 1[T>0] * 256 + 64T KiB
```

`T=32` 时：

```text
v1       =  2,304 KiB
baseline =  4,352 KiB
v0       = 20,480 KiB
```

全体 CTA.two 不是免费的。v1 明确接受的新增项只有 ownership 决定的
跨 CTA route；通过两 tile macro 复用 Q/dO 后，其逻辑 payload 为：

```text
X_v1(T) = 48T + 128*ceil(T/2) KiB
```

偶数稳态是 `112 KiB/pair/tile`，不是逐 tile 设计的
`176 KiB/pair/tile`。任何额外 GMEM reload、重复 GEMM、重复 P/dS image、
持久 exchange scratch、额外 workspace 或额外 dKV atomic 都不允许。

## 1. 为什么必须五类全部 CTA.two

此前评估过同一 kernel 内混用 CG2 与 CG1。这个方向已经被硬件工具链否决，
不是偏好问题：

```text
ptxas error:
Function ... uses single CTA(.cta_group::1) and CTA pair
granularity(.cta_group::2) and that is not allowed.
```

证据：

- [`correctness.log:13`](agents/dev_pipeline/trace_archive/20260726T151851Z_score-cg2-a0-rank4-r2s-r4/validation/logs/correctness.log)
- [`score_only_cg2_a0/REPORT.md`](agents/workspaces/score_only_cg2_a0/REPORT.md)

因此 v1 增加以下不可放宽的编译合同：

```text
Every tcgen05.mma / CuTe TiledMma in the main kernel:
    CtaGroup.TWO

Number of CG1 tiled-MMA issue sites:
    0
```

CTA-local TMA/load 指令不属于这个 MMA granularity 合同；禁止的是在同一
kernel 的 Tensor Core MMA 中混入 `CtaGroup.ONE`。

## 3. v0 必须解决的 6+2

两个 load 问题单列：

| ID | v0 问题 | v1 验收 |
|---|---|---|
| L1 | 主输入 GMEM load 放大 | 达到 `1[T>0]*256+64T KiB` |
| L2 | Q/dO 每 N64 重载，K 在 score/gradient 重载 | 每个 logical input 只有一个 G2S producer |

其余六项：

| ID | v0 问题 | v1 验收 |
|---|---|---|
| P1 | P/dS 为不同 ownership 重复 publication/image | P 一次直接发布；dS 一份 destructive transform |
| P2 | `dV -> WAIT_Q -> dK -> dQ` 串行 | dQ-first；Q_D 与 dO_D 并发 materialize，dV 后不再 G2S refill |
| P3 | exchange/barrier 暴露在 MMA 关键路径 | route 有明确 lookahead；IKET 中不允许稳态暴露等待 |
| P4 | uniform `3×48 KiB` FIFO 浪费和 HOL | 两个 typed 32 KiB stage，无 48 KiB slot |
| P5 | context detach/reducer ring/W7 侵入数据路径 | 单一 immutable `TileCtxRing[4]`，无 detach、无第二份 reducer context |
| P6 | 五个 CG2 的收益与成本不匹配 | 全 CG2 保留 half atomic；ownership route 达到 macro 容量下界 |

## 4. 数学与 ownership

逻辑数学不变：

```text
S[h,n]  = Σd Q[h,d]  K[n,d]
P[h,n]  = softmax(S)[h,n]
dP[h,n] = Σd dO[h,d] K[n,d]
dS[h,n] = softmax_backward(P,dP)[h,n]

dV[n,d] = Σh P[h,n]  dO[h,d]
dK[n,d] = Σh dS[h,n] Q[h,d]
dQ[h,d] = Σissued_tile Σn dS[h,n] K[n,d]
```

五类 GEMM 全部是 CG2：

- S/dP：结果按 `owner_H` 分给两个 CTA，D512 由四个 D128 chunk 完整归约；
- dV/dK：结果按 `owner_D` 分给两个 CTA，H128 在 CG2 内完整归约；
- dQ：结果按 `owner_D` 分给两个 CTA，每 tile 对 N64 完整归约，跨 tile
  累加在 persistent FP32 TMEM。

ownership route 只是 BF16 value 的置换，不做算术：

```text
Q,dO : H-owner -> D-owner
K    : N-owner -> D-owner
P,dS : H-producer -> N-owner
```

因此 dQ 先于 dV/dK 不改变依赖；dV/dK 只依赖 P/dS 与 stationary Q/dO，
不依赖 dQ 的数值结果。

### 4.1 计算量

每个 N64 tile、每类 GEMM：

```text
2 * H128 * N64 * D512 = 8,388,608 FLOP
```

总计：

```text
5 * 8,388,608 = 41,943,040 FLOP/tile
```

logical tiled-MMA call-step ledger（不是最终 SASS `tcgen05` 指令计数）：

```text
S/dP : 4 D128 chunks * 2 = 8 CG2 issues
dV/dK/dQ : 2 D rounds * 3 = 6 CG2 issues
total = 14 CG2 call steps/tile
CG1   = 0
```

没有重算 S/dP，没有增加 kernel launch。

### 4.2 dKV atomic

满 N64 tile：

```text
baseline = 2 * D512 * N64 = 65,536 scalar logical atomics
v1       =     D512 * N64 = 32,768 scalar logical atomics
```

dV overwrite、dK accumulate 后才 T2R/atomic。同一个 KV index 在不同
logical slot 中重复出现时仍分别 atomic，语义与 baseline 一致。

### 4.3 等价性引理

三个 partition 都是互斥完备划分：

```text
H = H_0 disjoint-union H_1
N = N_0 disjoint-union N_1
D = disjoint-union_{round,rank} D_round,rank
```

route 对每个 logical coordinate 是双射 `pi(x)=x`（只改变 owner/address，
不改变 value）。因此：

```text
Σrank Σh∈H_rank P[h,n]  dO[h,d] = Σh∈H P[h,n]  dO[h,d]
Σrank Σh∈H_rank dS[h,n] Q[h,d]  = Σh∈H dS[h,n] Q[h,d]
Σrank Σn∈N_rank dS[h,n] K[n,d]  = Σn∈N dS[h,n] K[n,d]
```

macro 共享 Q/dO 只让同一个 `Q_D/dO_D` value 被两个 tile 的不同
`P_j/dS_j` 消费，不在 tile 间做归约或混合。故每个输出 coefficient 恰好
出现一次；改变的是合法拓扑顺序，不是计算图。

## 5. 为什么跨 CTA exchange 不可能为零

对于两个二维 ownership 的均匀二分，一半元素 owner 不同：

```text
Q   H->D : 1/2 * H128 * D512 * 2B = 64 KiB
dO  H->D :                              64 KiB
K   N->D : 1/2 * N64  * D512 * 2B = 32 KiB
P   H->N : 1/2 * H128 * N64  * 2B =  8 KiB
dS  H->N :                               8 KiB
```

若每个 tile 都独立 materialize：

```text
64 + 64 + 32 + 8 + 8 = 176 KiB/pair/tile
```

这只是 ownership payload，不包含本地 S2R/R2S 指令和 barrier。

Q/dO 对同一 query 的所有 N tile 相同，所以逐 tile 支付 128 KiB 是可避免
的重复。v1 同时保留两个 tile 的 K/P/dS，并让两个 tile 共享一个 Q_D/dO_D
view：

```text
K + P + dS                  = 48 KiB/tile
Q + dO                      = 128 KiB/macro
macro width                 = 2

X_v1(T) = 48T + 128*ceil(T/2) KiB
```

偶数稳态：

```text
X_v1/T = 48 + 128/2 = 112 KiB/tile
```

odd tail 只有一个 tile，但仍需要完整 Q/dO view，尾 tile 为 176 KiB。

在“不增加第三套 K/P/dS resident stage、不重算 score/math”的约束下，
macro width 不能超过 2。一个 tile 在进入共享 Q/dO gradient 前必须同时
保留 `K_D 32 KiB + P/dS 16 KiB`；现有两套 stage 已经占满 224 KiB
payload。第三个 tile 至少再要 48 KiB/CTA，或把中间量 spill/recompute，
都属于禁止的新成本。两个 64-column dKV TMEM slot又正好允许同一 D round
先发两个 tile 的 dV，再在 Q_D ready 后分别累加 dK。

### 5.1 本地 materialization 不能藏账

remote payload 不是全部片上工作。按 logical source read + destination
write 计数，且不重复计算已经包含在 destination write 中的 remote bytes：

```text
Q+dO D-view:
  2 tensors * (128 KiB read + 128 KiB write)
  = 512 KiB/macro
  = 256 KiB/tile in even steady state

K N->D:
  retained quadrant byte-compatible fast path = 64 KiB/tile
  full capture + full rewrite envelope         = 128 KiB/tile

P direct final publication                     = 16 KiB/tile

dS initial publication + H->N:
  outgoing-only fast path                      = 32 KiB/tile
  full capture + full rewrite envelope         = 48 KiB/tile
```

所以偶数稳态的 route/publication 片上 access envelope 是：

```text
368 .. 448 KiB/pair/tile
```

其中 `112 KiB/tile` 是跨 CTA 子集，不能再加一次。该 envelope 不包含
原始 G2S deposit 和 MMA operand read。它说明 v1 是“用一次片上
materialization 换掉重复 GMEM”，不是免费消失；CP0 优先争取
quadrant-compatible fast path，最终必须由 NCU/IKET 证明这部分没有成为新
瓶颈。

## 6. v1 数据面

### 6.1 Stationary Q/dO

确认 `T>0` 后，每 CTA 一次 G2S：

```text
sQ_H[rank]  = Q[H_rank, D512]    # 64 KiB/CTA
sdO_H[rank] = dO[H_rank, D512]   # 64 KiB/CTA
```

生命周期：

```text
first issued context
-> Q/dO G2S
-> all score + all macro D-view materializations
-> final source-safe/drain
-> dQ epilogue may reuse dead operand storage
```

`T=0` 不加载 Q/dO，直接走 uniform zero-dQ/empty drain。

### 6.2 两个 32 KiB multifunction operand stages

Score phase：

```text
op[0] = K_N(tile a): N32 x D512 / CTA
op[1] = K_N(tile b): N32 x D512 / CTA
```

每个 K tile 只有 `owner_N(n)` 一个 GMEM producer。SDP operand-safe 后：

```text
K_N -> K_D in the same 32 KiB stage

K_D[rank,round] =
    K[N64, D_rank(round)]       # 16 KiB/round/CTA
```

每个 tile 的两个 dQ round last-use 后，对应 K stage 立即死亡。`op[0]`
可在 tile b 仍执行 dQ 时先开始 dO(r0) materialization；`op[1]` 在 tile b
dQ 完成后开始 Q(r0) materialization。随后两者成为：

```text
op[0] = dO_D[round]: H128 x D128 / CTA
op[1] = Q_D [round]: H128 x D128 / CTA
```

这两个 view 被 macro 的 tile a、tile b 依次消费。

### 6.3 两个 16 KiB P/dS stages

每个 macro lane 一个：

```text
pd[j]:
  P_N  = H128 x N32 / CTA       # 8 KiB
  dS   = H64  x N64 / CTA       # 8 KiB, initially H-owner
```

P 不需要 H-owner consumer。math registers 按 logical `(h,n)` 直接写：

```text
local value  -> local P_N destination
remote value -> peer P_N destination
```

所以每个 P 元素只 publication 一次，没有 P_H 副本和 xchg source image。

dS 必须先供 dQ 使用，因此：

```text
dS_H_FULL
-> both dQ rounds operand-safe
-> capture outgoing off-diagonal values
-> pair CAPTURED barrier
-> local/peer stores overwrite the same stage into dS_N
-> dS_N_FULL
-> both dK rounds operand-safe
-> EMPTY
```

同一时刻只有一份 dS image。

### 6.4 Direct register-to-DSM route

224 KiB payload 后只剩 3 KiB control 空间，v1 禁止持久 xchg scratch。主
路径固定使用 register capture + local/peer destination store：

```text
1. arm destination transaction barrier with exact expected bytes
2. load every source value that may be overwritten into distributed registers
3. cluster-uniform CAPTURED barrier
4. write local destinations and peer destinations
5. local writer join/fence and remote transaction completion
6. destination FULL / pair-ready
7. consumer may start
```

关键不变量：

```text
all source captured before first overlapping destination write
destination FULL before MMA reads it
register source retained until async remote transaction source-safe
```

这避免如下错误：

```text
CTA0 writes CTA1.dst while CTA1's same bytes are still CTA1.src
CTA1 writes CTA0.dst while CTA0's same bytes are still CTA0.src
```

可复用的开源 primitive 是
`st.async.shared::cluster.mbarrier::complete_tx`；FlashAttention 的
[`copy_utils.py`](https://github.com/Dao-AILab/flash-attention/blob/5835c733e7e9c07606b045255768e8a7e9e851bd/flash_attn/cute/copy_utils.py)
已有 register-to-peer FP32x4 实现。本项目仍必须为 packed BF16 和目标
swizzle 做独立 CuTe/PTXAS probe，不能据此假设 lowering 自动成立。

寄存器 envelope：

```text
K outgoing half capture, 256 threads : nominal <= 16 x 32-bit regs/thread
K full rewrite fallback, 256 threads : nominal <= 32 x 32-bit regs/thread
dS outgoing capture, 128 threads     : nominal <=  8 x 32-bit regs/thread
dS full capture/rewrite, 128 threads : nominal <= 16 x 32-bit regs/thread
```

`local memory = 0`、`spill = 0` 是硬门。若 direct BF16 R2DSM 或 layout
route 失败，不自动切到占用另一 op stage 的 bulk alias；该 fallback 会破坏
`GRAD || LOAD(next)`，不属于本 v1。

## 7. 两 tile macro pipeline

令：

```text
a = issue_seq 2j
b = issue_seq 2j+1, if present
```

### 7.1 Score / math

```text
LOAD K(a)
-> SDP(a)
-> K_N(a) capture/route to K_D(a)

LOAD K(b)
-> math(a) T2R releases S/dP TMEM
-> SDP(b) || remaining math(a) + P/dS publication + K route(a)
-> K_N(b) capture/route to K_D(b)
-> math(b)
```

S/dP TMEM 只有一代。`math(a)` 先 T2R 并释放 TMEM，随后 FP32
softmax/dS 和 publication 与 `SDP(b)` overlap。这保留原始设计的：

```text
SDP(i+1) || MATH(i)
```

### 7.2 dQ-first

当 K_D 与 dS_H ready：

```text
dQ(a,r0)
dQ(a,r1)
  -> K(a) stage dead
  -> start dS(a) H->N
  -> start dO_D(r0) materialization in op[0]

dQ(b,r0)
dQ(b,r1)
  -> K(b) stage dead
  -> start dS(b) H->N
  -> start Q_D(r0) materialization in op[1]
```

dQ 提前的作用：

- 释放两个 32 KiB K_D stage；
- 允许 dS destructive transform；
- 删除 v0 的 `dV -> G2S Q -> WAIT_Q -> dK -> dQ`；
- 不改变任何数值依赖。

### 7.3 Macro-shared dV/dK

round 0：

```text
finish dO_D(r0) -> op[0]            # 已与 tile-b dQ / dS route overlap
finish Q_D (r0) -> op[1]            # dV 执行期间继续完成

dV(a,r0) -> dKV slot a, overwrite
dV(b,r0) -> dKV slot b, overwrite

dK(a,r0) -> dKV slot a, accumulate
dK(b,r0) -> dKV slot b, accumulate

T2R/atomic slot a,b
```

一旦两个 dV operand-safe，`op[0]` 不再需要 r0 dO，可在 r0 dK 使用
`op[1]` 时 refill：

```text
materialize dO_D(r1) || dK(a/b,r0) || REDUCE(r0)
```

一旦两个 r0 dK operand-safe：

```text
materialize Q_D(r1)
```

round 1 同样执行。最后：

```text
dV(a/b,r1) operand-safe
  -> op[0] becomes K(next a) load stage
  -> LOAD K(next a) || dK(a/b,r1) || REDUCE

dK(a/b,r1) operand-safe
  -> op[1] becomes K(next b) load stage
  -> LOAD K(next b) || SDP(next a)
```

因此原始第二条目标在 macro 后半仍成立：

```text
GRAD(current macro) || LOAD(next macro) || REDUCE
```

### 7.4 MMA leader sequence

抽象顺序：

```text
SDP(a), SDP(b),
dQ(a,r0/r1), dQ(b,r0/r1),

for r in {0,1}:
    dV(a,r), dV(b,r),
    dK(a,r), dK(b,r),

SDP(next a), SDP(next b), ...
```

这是在 v0 core pipeline 上做两 tile batching；没有把 N_TILE 改为 N128，
每个数学 GEMM 仍是 native N64。

本节的 MMA 列表描述 leader issue order，不把 issue 当 completion。任何
`K/dS` rewrite、`dO/Q` refill、PD recycle 和 next-K load 都只由对应
CG2 consumer 的独立 `operand_safe` generation 释放；形式化 DAG 对
`dQ/dV/dK issue` 与 `*_operand_safe` 使用不同节点。

## 8. TMEM

```text
S                                64 columns
dP                               64 columns
dKV macro lane a                 64 columns
dKV macro lane b                 64 columns
dQ D-round 0                    128 columns
dQ D-round 1                    128 columns
-------------------------------------------
total                           512 columns
```

关键变化是 dKV 两个 slot 的含义：

```text
v0       : often treated as D-round ping-pong
v1 macro : tile a / tile b within the same D round
```

每个 round：

```text
dV(a/b) overwrite
-> dK(a/b) accumulate
-> reducer T2R
-> slot EMPTY
-> next D round may overwrite
```

atomic 不持有 TMEM。dQ 两个 round 的 accumulator 跨全部 macro 常驻。

## 9. SMEM 与 control envelope

每 CTA：

```text
stationary Q_H                         64 KiB
stationary dO_H                        64 KiB
multifunction op[0]                    32 KiB
multifunction op[1]                    32 KiB
P/dS stage[0]                          16 KiB
P/dS stage[1]                          16 KiB
------------------------------------------------
data payload                          224 KiB
                                     229,376 B
```

SM100 上限：

```text
232,448 B
```

只剩：

```text
3,072 B
```

control envelope 固定为：

```text
TileCtxRing[4]       4 * 272 B        1,088 B
traversal descriptor                      288 B
stats/control                             640 B
stream/macro state                         64 B
最多 96 个 64-bit mbarrier                768 B
alignment/TMEM-control reserve            224 B
------------------------------------------------
control envelope                        3,072 B
```

这不是“已经编译通过”的声明，而是不得突破的设计上界：

```text
cute.size_in_bytes(SharedStorage) <= 232,448
actual mbarrier slots             <= 96
persistent exchange scratch        = 0
```

任何 layout `cosize` 膨胀、padding、额外 4/8/16 KiB xchg 或常驻 dQ
epilogue buffer都会使候选失败。dQ epilogue 必须在主循环和 remote transaction
全部 drain 后复用一个死亡的 32 KiB op stage。

## 10. Metadata / reducer

v1 删除：

```text
IssuedCtxRing[2] -> scalar detach -> ReducerCtxRing[2]
```

改为：

```text
immutable TileCtxRing[4]
```

每个 context 只写一次，包含 logical tile、64 个 KV index、valid mask 和
`issue_seq`。load、math、MMA、reducer 读取同一份 context；没有 272-byte
per-tile detach。

生命周期：

```text
descriptor publishes context
-> K load / math / grad
-> both dKV round reducers consume indices
-> atomic completion
-> context RETIRED
```

四槽覆盖当前 macro 两 tile和下一 macro 至多两 tile。ring full 只允许阻止
未来 descriptor admission，不能阻塞当前 P/dS ready 或当前 grad。

descriptor role 与 Q/dO materialization / dS route role 不共用一个关键 warp；
具体 warp ID 和 `setmaxnreg` 在实现时决定。

## 11. Barrier 与 lifetime 合同

### 11.1 通用

- leader CTA 的 elected thread 发射 CG2 MMA；follower 不重复发射；
- follower 必须参加本 CTA load、route、math、reduce 和全部 generation；
- 所有 active-lane 判断由两个 CTA 共享的 issued stream 决定，必须
  cluster-uniform；
- current macro 的 route/refill 高于 future G2S，禁止 future load 抢占当前
  macro 唯一可用 stage；
- `issue != completion`；remote async store 必须由 transaction completion
  或等价 source-safe/full 信号闭合。

### 11.2 Stage last-use

```text
K_N stage:
  SDP operand-safe + source captured -> may become K_D

K_D stage:
  both dQ rounds operand-safe -> may become macro dO/Q stage

P_N:
  both dV rounds operand-safe -> EMPTY

dS_H:
  both dQ rounds operand-safe -> may become dS_N

dS_N:
  both dK rounds operand-safe -> EMPTY

dO_D(round):
  both macro-lane dV operand-safe -> refill/reuse

Q_D(round):
  both macro-lane dK operand-safe -> refill/reuse

dKV TMEM:
  reducer T2R complete -> EMPTY; atomic may continue
```

### 11.3 Prologue / odd tail / drain

- `T=0`：不加载 stationary Q/dO；两个 CTA 走同一 empty protocol；
- `T=1` 或 odd tail：macro lane b 缺席，两个 CTA uniform skip lane-b
  events，不伪造 GEMM，不发错误 expected bytes；空的 `op[1]` 可在
  `dQ(a)` 期间预填 Q(r0)，`op[0]` 在 dQ(a) last-use 后转成 dO(r0)；
- odd tail 的 dKV slot1、PD stage1 和 reducer team1 不产生 full/empty/
  atomic generation；
- pairing 按 `issue_seq`，不按带 hole 的 traversal slot；
- final drain 等待所有 remote store source-safe、destination full consumer、
  reducer T2R/atomic context retire；
- TMEM deallocation 前执行完整 cluster rendezvous；
- kernel 运行超过 10 秒按 workspace 合同判定死锁。

抽象 DAG 已由
[`agents/v1_design/verify_v1_contract.py`](agents/v1_design/verify_v1_contract.py)
检查为无环；具体 mbarrier phase/generation 仍需实现审计和 IKET 验证。

## 12. 6+2 关闭方式

### L1：GMEM 放大

```text
v0       = 640T
baseline = 1[T>0]*256 + 128T
v1       = 1[T>0]*256 + 64T       KiB
```

静态 unique-producer 证明加 NCU/TMA bytes 双验收。

### L2：每 tile 重复加载

- Q/dO 不进入 tile load queue；
- K score load 直接 route 给 dQ，gradient 不再 G2S K；
- Q/dO D-view 是片上 ownership materialization，且两个 tile 共享，不是
  GMEM reload。

### P1：P/dS 重复 publication

- P 每值从 math register 写一次 final N-owner destination；
- dS math 只写一次 H-owner image，last-use 后同一地址 destructive route；
- 不同时保留 `dS_dQ + dS_dK + xchg` 三份 image；
- math publication logical destination bytes 回到 P16+dS16 =
  `32 KiB/pair/tile`；额外 `16 KiB` remote 是全 CG2 ownership 下界。

### P2：WAIT_Q 串行

- dQ 提前并释放 K stage；
- Q_D 与 dO_D 同时 materialize；
- dV 执行期间 Q_D 应已在途/ready；
- dV 后不存在 Q GMEM refill。

若 IKET 仍观察到稳态 `WAIT_Q_D` 暴露，则该候选未解决 P2。

### P3：exchange 未隐藏

- K route 与 math/另一 K load overlap；
- dS H->N 与另一 tile dQ、dO materialization/dV overlap；
- Q_D 与 dO_D 并发生产；
- round1 dO refill 与 round0 dK/reducer overlap。

静态 DAG 只证明可以 overlap；最终以 IKET wait range 判定是否真正隐藏。

### P4：uniform FIFO

删除 `3×48 KiB` generic task FIFO。两个 32 KiB stage 具有明确状态：

```text
EMPTY -> K_N -> K_D -> dO_D/Q_D -> K_next
```

没有每槽 8 KiB 浪费，也没有 F/B/BQ 六代 whole-slot task。

### P5：metadata critical path

单一 immutable context、无 detach、无第二 ring；reducer 不持有数据 stage
credit。descriptor 只在 admission 边界等待空 context。

### P6：CG2 收益/成本

- 遵守 PTXAS 单一 granularity；
- K 只 G2S 一次；
- dKV atomic 减半；
- dQ 保持 non-atomic D ownership；
- Q/dO exchange 由两 tile 分摊；
- remote payload 达到当前资源约束下的 macro 下界。

## 13. “没有引入新成本”的精确定义

字面上的“全 CG2、GMEM exactly-once、跨 CTA 0 字节”无解。用户已经明确
接受必要的跨 CTA exchange，因此 v1 的合同是：

允许且必须计账：

```text
remote payload = 48T + 128*ceil(T/2) KiB
每个 produced ownership view 一次必要的 local S2R/R2S
对应的 source-safe / destination-full barrier
有限、无 spill 的 route registers
```

禁止：

```text
额外主输入 GMEM
额外 GEMM / FLOP
第二次 kernel launch
额外 workspace
额外 logical dKV atomic
重复 P/dS live image
持久 exchange scratch
逐 tile重复 Q/dO materialization
bulk alias 导致的 next-load overlap 丢失
```

允许项也不能无条件接受其延迟。若 remote/local route 或 barrier 在稳态暴露，
导致端到端不快于同轮 baseline，v1 判失败。

## 16. 实现门槛

### CP0：最小 lowering probes

在进入完整 kernel 开发前必须分别通过：

1. 五类 TiledMma 全 CG2，PTXAS 中无 `.cta_group::1` MMA；
2. Q/dO stationary score layout -> D-view destination 的 coordinate route；
3. K_N score-B -> K_D dQ-A 的 in-place capture/rewrite；
4. P BF16 direct register-to-peer final publication；
5. dS_H -> dS_N source-safe destructive route；
6. compiled `SharedStorage <= 232448 B`；
7. TMEM offsets/layout 正好 512 columns；
8. PTXAS `spill stores = spill loads = 0`，无 local-memory route fragment。

任一失败都回到数据布局设计，不用额外 GMEM reload 或持久 scratch 掩盖。

### CP1：correctness / deadlock

至少覆盖：

```text
dense
lengths
holes
all_empty
partial N64
odd issued count: T=1,3,31
even issued count: T=2,32
repeated KV index
```

验证 P/dS mask、dQ first-tile overwrite/后续 accumulate、dKV atomic 和 odd
macro phase。kernel 超过 10 秒判死锁。

### CP2：流量 / IKET / NCU

必须实测：

```text
Q/dO G2S count                     = once/query
K G2S logical bytes                = 64T KiB/pair
main input total                   = 1[T>0]*256 + 64T KiB
logical remote payload             = 48T + 128*ceil(T/2) KiB
dense dKV logical atomics          = 32768T
spill/local memory                 = 0
```

IKET 重点：

- `WAIT_Q_GMEM` 不再存在；
- `WAIT_Q_D`、`WAIT_K_ROUTE`、`WAIT_DS_ROUTE` 不在稳态暴露；
- `SDP(next)||MATH(current)` 和 `GRAD||LOAD||REDUCE` 确实重叠；
- barrier generation 成对，source-done 在 alias/reuse 前完成；
- odd tail 与 drain 无 CTA rank skew。

### CP3：性能

只使用 workspace 固定 harness。最终合同：

```text
correctness pass
deadlock = false
latency_v1 < same-run latency_baseline
```

“比 v0 快”不是最终验收；目标是超过 baseline。

## 17. 暂不固定的实现细节

为避免过度设计，本文不提前固定：

- 精确 warp ID、每类 warp 数量和 `setmaxnreg` 数值；
- packed BF16 remote-store 的最终 vector width；
- 各 swizzle 的具体 CuTe type；
- 96 个 barrier budget 内的最终 barrier 名称与 ID；
- dense fast path 与 sparse path 是否共用 context template；
- dQ epilogue的具体 T2R/R2S vectorization。

这些细节可以在 CP0/开发阶段决定，但不得改变本文的数学、GMEM、
ownership、macro reuse、资源上限和全 CG2 合同。
