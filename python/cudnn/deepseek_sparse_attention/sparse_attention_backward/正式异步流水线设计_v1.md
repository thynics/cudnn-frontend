# SM100 DSA backward v1：正式异步流水线设计

> 状态：trace-driven 设计草案，尚未修改 canonical kernel。
> 目标 shape：B200 / BF16 / H128 / D512 / native N64 / 2-CTA cluster。
> 数据面和数学合同继承 [`优化设计文档_v1.md`](优化设计文档_v1.md)；本文只固定
> role graph、stage 生命周期、合法 overlap 和落地 gate。

## 0. 结论

当前 canonical v1 是已经通过 correctness 的 `v1-A0 sequential macro
bring-up`，不是正式流水线。它用 8 warps/CTA 执行正确的数据 ownership，
但 load、MMA、math、route 和 reduce 大量复用同一批 warp，并由整 CTA
barrier 和 cluster rendezvous 串成 phase。

正式版 `v1-A1` 不继续在 A0 内逐个删除 barrier，而采用：

```text
v1 的 224-KiB typed data plane
+ v0 已验证过的 20-warp persistent-role 骨架
+ 按真实 last-use 拆开的 completion streams
+ two-tile macro / TileCtxRing[4]
```

核心目标：

```text
SDP(next) || MATH(current) || ROUTE(current)

dQ(current)
  || dS route
  || Q/dO materialization

DO_EMPTY(current round)
  -> dO materialization(next round)
     || dK(current round)

Q_EMPTY(current round)
  -> Q materialization(next round)
     || dKV result/T2R/atomic(current round)

GRAD(current macro)
  || LOAD(next macro)
  || REDUCE(current macro)
```

steady state 中不得再有 640-thread 跨角色 `main_barrier`，也不得用无条件
whole-cluster rendezvous 串起无关 role。role-local join、destructive-route
capture barrier 和 pair mbarrier 仍然是正确性协议的一部分。

## 1. 证据与边界

### 1.1 源码事实

canonical 类和 kernel docstring 已明确说明当前实现是顺序 bring-up：

- `dsa_bwd_sm100_2cta_v1.py:8151-8161`
- `dsa_bwd_sm100_2cta_v1.py:9553-9560`

当前 macro 顺序为：

```text
decode a/b
-> Q/dO/stats load and wait
-> K(a), K(b) load and wait
-> SDP(a) + complete math(a)
-> SDP(b) + complete math(b)
-> route P(a), P(b)
-> route K(a), K(b)
-> dQ(a), dQ(b) with immediate consumer waits
-> route dS(a), dS(b)
-> for r:
       materialize Q/dO(r)
       dV+dK(a,r) -> T2R -> atomic
       dV+dK(b,r) -> T2R -> atomic
```

对应主循环位于 `dsa_bwd_sm100_2cta_v1.py:10061-10656`。

### 1.2 B200 证据

trace 的直接观察（`completion` 是所选 tile 最后一个

这里的 active union 是每个 tile 全部已选软件 span segment 的 union，不是

```text
S/dP + math(a/b)        4.704 .. 28.224 us
```

```text

```

这是包含 inclusive wait/barrier 且忽略 overlap 的绝对和，不等于 wall time。
它只能说明 transport-associated inclusive scopes 的绝对和较大，足以把
transport 从同一 collective phase 中拆出来做独立验证。

### 1.3 当前 trace 不能证明什么

当前 98% 左右的 role overlap 不能解释为有效并行：

- `ROLE_*` 只在 kernel 入口按 warp 静态分类；
- route/reduce 随后由全部 8 warps collective 执行；
- `LOAD_QDO`、`LOAD_K`、`ROUTE_*`、`MAT_QDO` span 包含 CTA/cluster wait；
- 所以同一 collective scope 会同时出现在 MMA、MATH、KV_LOAD 轨道。

另有两个必须修正的语义：

1. 当前 `LOAD_QDO` 包含 TMA wait 和 rendezvous，不是 semantic map 所写的
   issue-only span。
2. 当前 `_issue_dq_stage_v1` 在 outer `r=0` 一次发射两个物理 round，
   outer `r=1` 不发射工作。因此现有 `dQ_ISSUE(i,r)` 不能按 round 解释。

IKET 仍然只能观察软件到达 issue/wait 的时刻，不能伪造 TMA/UMMA/atomic
retire timestamp。

前三 tile 又包含 cold start 和 macro 边界。正式流水线验收必须补采中间完整
macro，例如 `i=9..12`。

## 2. 不变量

正式流水线不得改变：

```text
CG2-only five-GEMM math
FLOP / logical MMA count
one K GMEM producer per logical tile
Q/dO GMEM load once for T>0
dKV logical atomic count
P/dS numerical precision and ownership
compact issue_seq semantics
T=0 / hole / odd-tail behavior
```

资源上限：

```text
SharedStorage <= 232,448 B
data payload   = 224 KiB
TMEM columns   = 512
context stages = 4
op stages      = 2 x 32 KiB
P/dS stages    = 2 x 16 KiB
mbarrier slots <= 96
local memory   = 0
spill          = 0
```

禁止用第三套 operand stage、persistent exchange scratch、额外 workspace、
额外 GMEM reload 或重算来换 overlap。

本文只设计 fused backward main kernel 内部流水线。host 侧
`sum_OdO -> main -> convert_dKV -> sum_dSink` 仍按同一 CUDA stream 顺序
执行，不假设跨 kernel overlap；它们需要另立 contract 和 Release A/B。

## 3. Persistent role graph

首版使用 v0 已验证过的 20 warps/CTA。224-KiB SMEM 已把 occupancy 限制为
每 SM 一个 CTA，8 -> 20 warps 不再减少 CTA residency；但寄存器预算仍需
PTXAS/NCU 验收。

| Warp | 正式角色 | 主要职责 |
|---|---|---|
| W0-W3 | `TRANSPORT` | K gather及各 warp 自己的 cp.async group、dO_D materialization、next-K prefetch |
| W4 | `LOAD_CTRL` | stationary TMA、stats、op credit、W0-W3/zero-fill join 与 `K_N_FULL` 发布 |
| W5 | `MMA` | rank0 唯一 CG2 issuer；不做 math、route、reduce |
| W6 | `ROUTE_CTRL` | DSM transaction、phase/source-safe/full 发布 |
| W7 | `DESCRIPTOR` | traversal、TileCtxRing[4] admission、sticky END |
| W8-W11 | `MATH` | S/dP T2R、FP32 P/dS、Q_D materialization、dQ epilogue |
| W12-W15 | `LANE_A` | macro lane a 的 K/P/dS route 与 dKV reduce |
| W16-W19 | `LANE_B` | macro lane b 的 K/P/dS route 与 dKV reduce |

角色只在入口分支一次，此后每个角色运行自己的 persistent loop。steady state
不得借用“所有 resident warps”完成某个 helper。

所有 helper 都必须接收显式 `role_tidx` 和 role participant count。A0 中按
`tidx=0..255` 编写的 Q/dO materialize、K/dS route 和 T1d reducer 不能直接
从非连续 persistent role 调用。

`LANE_A/B` 的首选 lowering 是各 128 threads 独立处理一个 macro lane。
CP0 必须验证：

- K full-capture route 不 spill；
- 128-thread dKV T2R 覆盖完整 N64；
- 两 lane 同时 DSM route 不发生 phase 交叉。

若 128-thread reducer 不可行，可暂时保留 8-warp T2R，但仍必须让 MMA
producer 在 T2R 后立即继续，不能等待 atomic 结束。该 fallback 不改变
stage/DAG，只降低 reducer 并行度。

`LANE_A/B` 内部的 route、T2R 和 atomic 是单一 role service queue，彼此
不能假装同时执行。目标 overlap 发生在两个 lane 之间，以及 lane role 与
TRANSPORT/MMA/MATH 之间。若 trace 证明 atomic 与下一 macro route 冲突在
关键路径，再单独评估增加 staffing；首版不为不存在的 warp 预算做承诺。

## 4. Stage 状态机

### 4.1 TileCtxRing[4]

```text
EMPTY
-> DESCRIPTOR_WRITING
-> FULL(issue_seq, logical_tile, indices, valid mask)
-> readers active
-> both dKV rounds have detached/consumed atomic addresses
-> RETIRED
-> EMPTY
```

descriptor 是唯一 writer。load、math、MMA、route、reducer 只读。
首版允许 context 在两个 reducer atomic 完成后才 retire；之后可以在 reducer
把地址信息完整搬入寄存器后提前 retire。

### 4.2 两个 32-KiB op stages

even macro：

```text
op[0]:
EMPTY
-> K_N(a)
-> K_D(a)
-> dQ(a,r0/r1) aggregate INPUT_SAFE
-> dO_D(r0)
-> all-active-lane DO_SAFE(*,r0) -> DO_EMPTY(r0)
-> dO_D(r1)
-> all-active-lane DO_SAFE(*,r1) -> DO_EMPTY(r1)
-> K_N(next a)

op[1]:
EMPTY
-> K_N(b)
-> K_D(b)
-> dQ(b,r0/r1) aggregate INPUT_SAFE
-> Q_D(r0)
-> all-active-lane Q_SAFE(*,r0) -> Q_EMPTY(r0)
-> Q_D(r1)
-> all-active-lane Q_SAFE(*,r1) -> Q_EMPTY(r1)
-> K_N(next b)
```

`INPUT_SAFE` 与 `RESULT_DONE` 必须严格分开：

```text
INPUT_SAFE:
  operand full/empty protocol的 consumer-release generation
  决定 SMEM input 是否可覆盖

RESULT_DONE:
  accumulator completion被 result consumer观察到
  决定 TMEM 是否可 T2R
```

两者都不是 IKET issue end。实现分别使用 operand
`PipelineAsyncUmma`-style full/empty 协议和 result
`PipelineUmmaAsync`-style completion 协议，不能由一个 generic
`done_pipeline` 代替。

odd tail 时 lane b 不产生伪 full/empty generation。空闲 `op[1]` 可以在
`dQ(a)` 期间提前 materialize `Q_D(r0)`。

### 4.3 两个 P/dS stages

每个 macro lane 独立：

```text
P:
EMPTY
-> P publication in flight
-> P_N_FULL
-> both dV rounds operand-safe
-> P_SAFE
-> EMPTY

dS:
EMPTY
-> dS_H_FULL
-> both dQ rounds enqueued
-> one aggregate DQ_INPUT_SAFE
-> CAPTURED
-> dS_N_FULL
-> both dK rounds operand-safe
-> DS_SAFE
-> EMPTY
```

正式目标是 math registers 直接发布到 final `P_N`，删除独立 `ROUTE_P`。
为降低首个结构 patch 风险，可以先保留已验证的 P full-rewrite route，但它
必须在 lane role 上异步执行；direct publication 作为独立后续 patch。

### 4.4 TMEM

```text
S / dP:
  one physical generation each
  CG2 done -> math T2R -> tmem-load fence -> immediate release
  FP32 math does not retain S/dP TMEM

dQ:
  two persistent D256 accumulators
  all tiles accumulate
  final completion -> epilogue T2R/store

dKV lane a/b:
  EMPTY
  -> dV overwrite
  -> dK accumulate
  -> FULL
  -> reducer T2R + tmem-load fence
  -> EMPTY
  -> atomic continues from registers
```

## 5. 必须保留与必须删除的边

### 5.1 硬 happens-before

```text
Ctx_i -> K load / valid mask / dKV atomic destination

Q_READY + K_N_i_READY  -> S_i issue
dO_READY + K_N_i_READY -> dP_i issue

S_i RESULT_DONE  -> S T2R  -> S TMEM release
dP_i RESULT_DONE -> dP T2R -> dP TMEM release
S-reg + dP-reg + stats -> P_N_i + dS_H_i

S_i and dP_i K_INPUT_SAFE -> destructive K_N_i -> K_D_i
K_D_i + dS_H_i -> dQ_i
both dQ rounds enqueued -> one aggregate DQ_INPUT_SAFE
  -> K_D overwrite + dS_H -> dS_N

P_N_i + dO_D_r -> dV_i,r
dS_N_i + Q_D_r -> dK_i,r
dV_i,r issue
  -> same W5 program order on the same t_dkv accumulator
  -> dK_i,r issue

DO_SAFE(i,r) from every active lane -> DO_EMPTY(r) -> dO_D_r reusable
P_SAFE(i) after both dV rounds -> P_EMPTY(i) -> P_N_i reusable
Q_SAFE(i,r) from every active lane -> Q_EMPTY(r) -> Q_D_r reusable
DS_SAFE(i) after both dK rounds -> DS_EMPTY(i) -> dS_N_i reusable
dK RESULT_DONE -> DKV_RESULT_DONE -> dKV T2R
dKV T2R fence -> TMEM slot release
dKV registers -> global atomic

all dQ RESULT_DONE -> direct TMEM-to-register-to-GMEM dQ epilogue
all TMEM users drained -> TMEM free
```

跨 CTA destructive route 还必须保持：

```text
arm destination
-> all source captured
-> pair CAPTURED
-> local/remote stores
-> source-safe + destination full
-> consumer
```

### 5.2 只是 A0 程序序，正式版删除

- Q/dO wait 完成后才能 issue stats；
- stats wait 完成后才能 load K；
- K(a) 完成后才能 issue K(b)；
- 完整 `MATH(a)` 后才能 issue `SDP(b)`；
- P route 必须早于 K route；
- lane a route 必须早于 lane b；
- 每个 dQ issue 后立即 wait；
- dKV lane a atomic 完成后才能 issue lane b；
- reducer atomic 完成后才能复用已释放的 TMEM；
- final dQ epilogue必须等待所有 dKV atomic；
- macro 完整 retire 后才 decode/load 下一 macro。

## 6. Completion streams

当前所有 S、dP、dQ、dV/dK 共用一个两级 `done_pipeline`，把不同
accumulator 和不同 consumer 的生命周期塞进同一 FIFO。正式版至少拆为：

| Stream | Producer | Consumer / release |
|---|---|---|
| `CTX_FULL/EMPTY[4]` | each CTA local descriptor + pair consensus | final context reader |
| `Q_FULL`, `dO_FULL`, `STATS_FULL` | issuing load role | score / math / materialize consumers |
| `K_N_FULL[2]` | W0-W3 join published by W4 | MMA score consumer |
| `S_RESULT_DONE`, `dP_RESULT_DONE` | MMA result protocol | math T2R |
| `K_INPUT_SAFE[2]` | S+dP operand protocol fan-in | lane route |
| `K_D_FULL[2]` | lane route | dQ MMA |
| `P_N_FULL[2]`, `dS_H_FULL[2]` | math/route | dV / dQ |
| `DQ_INPUT_SAFE[2]` | both physical dQ issues aggregated once per lane | K recycle + dS route |
| `dS_N_FULL[2]` | lane route | dK |
| `dO_D_FULL[2]`, `Q_D_FULL[2]` | transport/math | dV / dK |
| `DO_SAFE[2][2] -> DO_EMPTY[2]` | dV operand release, active-lane fan-in per round | dO op-stage refill |
| `P_SAFE[2] -> P_EMPTY[2]` | both dV rounds consumed, fan-in per lane | P region recycle |
| `Q_SAFE[2][2] -> Q_EMPTY[2]` | dK operand release, active-lane fan-in per round | Q op-stage refill |
| `DS_SAFE[2] -> DS_EMPTY[2]` | both dK rounds consumed, fan-in per lane | dS region recycle |
| `DKV_RESULT_DONE[2][2]` | dK accumulator result protocol | lane reducer |
| `DKV_EMPTY[2]` | reducer T2R | next dKV producer |
| `DQ_FINAL_RESULT_DONE[2]` (`issued_count>0` only) | final physical dQ round | epilogue |
| `ROUTE_CAPTURED/DEST_FULL[...]` | local+peer route producer set | destination consumer |
| `ROLE_DRAIN[*]` | each role | final owner |

建议分别使用 typed operand full/empty pipeline 和 accumulator result
completion pipeline，而不是用一个 generic completion ring再由所有 warp
按程序序消费。dV 与 dK 可以拆 issue span和按资源归属的 operand-release
generation，但同一 `t_dkv` 只有 dK accumulate 后才能发布
`DKV_RESULT_DONE`；dV 后绝不允许 reducer T2R。`DO/Q` credit 按 round
复用，`P/dS` credit 按 lane 跨两个 round 保留，因此两组 release 不能共用
同一个 full/empty generation。odd tail 的 `DO/Q` fan-in expected arrivals
从 2 降为 1。

具体 barrier ledger 必须在实现前生成并静态检查：

```text
total slots <= 96
key = (cta_rank, stream, physical_stage, logical_generation)
每个 generation 声明精确 producer set 和 expected arrivals
expected arrivals 与 active lane/odd tail 一致
generation/phase 由 compact issue stream 的纯函数推导
END 不占普通 context/stage credit
```

推荐 generation：

```text
tile_generation  = issue_seq
macro_generation = issue_seq // 2
macro_lane        = issue_seq & 1
round_generation = 2 * macro_generation + round
phase             = logical_generation & 1
```

两 CTA 的 W7 各自写本地 context mirror，并在发布前对 compact stream 做
pair consensus；不允许两个 rank 依靠各自循环次数独立推进 phase。

## 7. 正式 macro 调度

### 7.1 Prologue

```text
DESCRIPTOR: ctx(a), ctx(b), ctx(next a), ctx(next b)

LOAD_CTRL:
  issue stationary Q/dO TMA
  issue stats

TRANSPORT:
  W0-W3 issue K(a), K(b) into independent op lanes
  each issuing warp commits/waits its own cp.async groups
  W4 joins cp.async completion and zero-fill before K_N_FULL

MMA:
  wait only for required input-full / output-credit boundary
```

Q/dO、stats 和 K 不在 producer 侧立即全局 wait。

### 7.2 Score / math / route

```text
SDP(a)
-> math(a) first performs S/dP T2R and releases TMEM

SDP(b)
  || remaining FP32 math(a)
  || K route(a)
  || P publication(a)

math(b)
  || K route(b)
  || P publication(b)
```

route priority：

1. `K_N -> K_D`，因为它解锁 dQ 和 op stage recycle；
2. P publication，因其只在稍后的 dV 使用。

direct `P_N` publication 完成后不再有 `ROUTE_P`。

### 7.3 dQ / dS / QdO

```text
dQ(a,r0/r1) issue back-to-back
  || P publication

observe aggregate DQ_INPUT_SAFE(a)
  -> dS(a) route
  -> start dO_D(r0) in freed op[0]

dQ(b,r0/r1)
  || dS(a) route
  || dO_D(r0)

observe aggregate DQ_INPUT_SAFE(b)
  -> dS(b) route
  -> start Q_D(r0) in freed op[1]
```

MMA leader不在每次 dQ issue 后进入 collective wait。lane owner 只在即将
覆盖 K/dS 时等待自己的一个聚合 input-safe token；该 token 只在两个
physical round 均 enqueue 后 release 一次。两个真实 issue marker 仍必须位于
各自物理 round 的 issue site，不能沿用 A0 的“outer r0 深发两 round、outer
r1 空调用”口径。

### 7.4 Gradient / reducer

必须把当前合并的 `_issue_dv_dk_final_v1` 拆成可独立审计的 dV/dK issue
phase和 input-safe generation，但仍保持同一 accumulator generation：

```text
dV(a,r0), dV(b,r0)
  -> all-active-lane DO_SAFE(*,r0) -> DO_EMPTY(r0)
  -> materialize dO_D(r1)

dK(a,r0), dK(b,r0)
  -> all-active-lane Q_SAFE(*,r0) -> Q_EMPTY(r0)
  -> materialize Q_D(r1)

reducer(a/b,r0):
  wait DKV_RESULT_DONE after dK accumulate
  -> T2R
  -> release dKV TMEM
  -> atomic from registers

dV/dK(a/b,r1)
  || r0 reducer/atomic
  || descriptor(next macro)
```

round 1：

```text
all-active-lane DO_SAFE(*,r1) -> DO_EMPTY(r1)
  -> op[0] starts K(next a)

all-active-lane Q_SAFE(*,r1) -> Q_EMPTY(r1)
  -> op[1] starts K(next b)

for each active lane i:
  dV(i,r0/r1) operand-safe -> P_SAFE(i) -> P_EMPTY(i)
  dK(i,r0/r1) operand-safe -> DS_SAFE(i) -> DS_EMPTY(i)

LOAD(next)
  || REDUCE/atomic(current)
  || SDP(next a)
```

### 7.5 Drain

- `issued_count == 0` 时不等待也不生成 `DQ_FINAL_RESULT_DONE`，epilogue role
  直接 zero-store dQ，再进入统一 role drain；不得用伪 tile 或普通 stage
  generation 表达该分支；
- odd tail 不产生 lane-b completion；
- 最后一次 dQ contribution 前为两个物理 round 分别 acquire final result
  generation，enqueue/fence 后分别 commit；
- epilogue 等待两个 `DQ_FINAL_RESULT_DONE[round]`，然后直接
  TMEM-to-register-to-GMEM store；不借用 op stage，可与最终 dKV atomic
  overlap；
- dQ T2R 到寄存器后只结束 dQ 数据生命周期，不能据此提前 free 整块 TMEM
  allocation；
- 等完 remote source-safe、destination consumer、context retire 和 role drain；
- 最后一次 cluster rendezvous 后才 free TMEM。

## 8. 新 trace 合同

正式流水线 trace 必须在真实 role branch 内打 marker，而不是沿用入口 role
去解释后续 collective helper。

IKET 自定义 event type 总数必须显式限制在 31 以内。最小 L3 语义使用少量
静态 family name，action 和动态 identity 由 payload 解码：

```text
ROLE
CTX
Q_LOAD / DO_LOAD / STATS
K
S / DP
MATH / P_PUBLISH / DS_PUBLISH
ROUTE
DQ / DV / DK / DKV
DQ_EPI
STAGE_WAIT
DRAIN
```

IKET range payload 只使用一个 packed i64，不传伪 tuple。sidecar schema 将其
解码为：

```text
(action, op, issue_seq, lane, round, stage, phase)
```

`macro=issue_seq//2` 可派生，不重复占位。具体 bit allocation 在
A1-contract 固定并加入 encode/decode round-trip 单测。

采集：

- first macro用于 prologue；
- 中间 `i=9..12` 用于 steady；
- last macro用于 odd tail/drain；
- 保留两个 CTA 和全部 role；
- renderer 按 stage/lane 重建状态，不把 envelope gap 当 active overlap。

验收必须分别报告：

```text
consumer full-wait ratio
producer empty-wait ratio
steady macro II
stage residence
role skew
route DSM issue -> software wait-return upper bound
prologue/drain fraction
```

最后一项是软件可观察上界，不是 remote store 的硬件 retire timestamp。

## 9. 分阶段落地

每一步只改变一个机制，并从当时 canonical v1 创建独立实验副本：

1. **A1-contract**：barrier ledger、stage enum、状态机模拟器、odd-tail/END
   静态检查。
2. **A1-roles**：20-warp persistent role skeleton + TileCtxRing[4]；先保持数学
   顺序，关闭 deadlock/correctness。
3. **A1-input**：stationary/stats/K producer issue 与 consumer wait 分离。
4. **A1-sdp**：独立 S/dP completion，达到
   `SDP(b) || MATH(a)`。
5. **A1-route**：只把 lane K/P route 从 collective phase 拆到独立 role。
6. **A1-dq**：加入真实 dQ physical-round issue marker、per-lane 聚合
   input-safe 和 final-result token，再接 destructive dS route。
7. **A1-qdo**：dO_D 与 Q_D 分离 materialize/publish，并按 input-safe 回收
   两个 op lane。
8. **A1-grad-issue**：拆 dV/dK issue span，并把 per-round `DO/Q` release
   与 per-lane `P/dS` release 分开；仍只在 dK result完成后发布 dKV
   accumulator。
9. **A1-reducer**：双 dKV slot result/T2R/empty 协议，T2R 后提前释放，
   atomic留在寄存器路径。
10. **A1-cross-macro**：round1 与 next-K / next-SDP overlap，补齐 empty、
   holes、odd tail 和 drain。
11. **A1-direct-p**：删除 `ROUTE_P`，恢复 direct final `P_N` publication。
12. **A1-enqueue**：流水线闭合后，再单独处理 S/dP enqueue 的 codegen/unroll；
   MMA issue span 内不加入动态 scheduler 或 polling。

每个实现变更都必须运行仓库的标准 B200 correctness、Release A/B、baseline /
candidate IKET 和 span-table gate。Trace build 只用于诊断，性能结论只来自
IKET off 的 Release。

## 10. Gate

### Static / codegen

- steady role loop 无 640-thread 跨角色 barrier；role-local/pair barrier 有完整
  participant ledger；
- CG1 issue site = 0；
- typed stage transition 无非法边；
- barrier generation/phase 无冲突；
- SharedStorage 和 mbarrier 数不超限；
- local memory / spill = 0；
- actual dQ round marker 与真实 issue site一一对应；
- dV、dK issue 可分别审计。

### Correctness / liveness

- dense、lengths、holes、all-empty；
- even macro、odd tail、T=0、partial N64；
- 两 CTA phase 一致；
- 10 秒 deadlock gate；
- dQ 与 dKV reference tolerance 不变。

### Trace structural acceptance

steady macro 中必须直接观察到：

```text
S/dP(next) starts before MATH(current) ends
lane a/b route can overlap
Q/dO(r1) starts before r0 atomic software scope ends
dKV TMEM release precedes atomic software scope end
K(next) starts before current macro reducer/atomic software scopes end
next SDP starts before current macro fully retires
```

若 only role overlap 上升、但 tile overlap、steady II 和 exposed wait 不改善，
不视为通过。

### Release performance

- paired/interleaved baseline vs candidate；
- 不跨 trace/release build 比时长；
- 同时报 kernel latency、macro II、register、spill 和 achieved traffic；
- 没有统计显著收益的结构 patch不进入 canonical v1。

## 11. 实现前必须关闭的 probe

1. 128-thread K route 的寄存器和 spill。
2. 128-thread per-lane dKV T2R 是否能覆盖 N64；否则选择 8-warp cooperative
   reducer但保持 producer/atomic 解耦。
3. 多个 typed operand full/empty 与 result completion pipeline 对不同
   consumer group 的 lowering 和 mbarrier 数量。
4. 两个 cp.async K groups 的 wait-group / zero-fill publication 协议。
5. dQ 真实 physical-round result completion 与 per-lane 聚合 K/dS
   input-safe 的最小 token 设计。
6. direct P_N DSM publication 的 packed-BF16/swizzle lowering。
7. 20-warp `setmaxnreg` 后的 PTXAS register budget。

这些 probe 关闭前，可以实现 role/context 骨架，但不应一次性提交完整异步
schedule。
