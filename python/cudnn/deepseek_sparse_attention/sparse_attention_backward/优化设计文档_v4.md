# 2-CTA Design v4：SM100 DSA GQA128 / D512 Backward

> 状态：V4 实现对齐规格。本文以
> [`优化设计文档_v2.md`](优化设计文档_v2.md) 为基础，并按
> [`dsa_bwd_sm100_2cta_v4.py`](dsa_bwd_sm100_2cta_v4.py) 当前实现更新；
> 静态审阅基线为 `9f3f81a`。V4 文件中的活动类仍名为
> `FlashAttentionDSABackwardSm100TwoCTAV2`，这是现有加载约定，不代表
> 实现版本仍是 V2；版本以模块文件名为准。
>
> V3 的留存测量为 14.28 ms、约 1.77x baseline latency。V4 尚无仓库内
> 完整的 correctness/performance/IKET 结果，因此本文不继承 V2 的
> 4.5–5.0 ms 预测；性能结论必须由 V4 自身验证产生。

## 0. 结论

```text
host 流程：sum_OdO/scaled_LSE -> V4 fused main -> dKV canonical convert
          -> sum_dSink
main kernel：
  cluster = (2,1,1)，每个 query token / batch 一个 2-CTA cluster
  CTA c 持有 H64_c = heads [64c, 64c+64)
  固定 BF16 输入、FP32 accumulator、GQA128、D=512、N tile=64
  640 threads/CTA（20 warps），SharedStorage <= 232448 B，TMEM=512 col
  S、dP、dQ、dV、dK 的实际 MMA issue 全部使用 CtaGroup.TWO
```

V4 保留 V2 的数据面原则：

1. Q/dO/P/dS 保持 H-native，不做跨维度 re-ownership。
2. dV/dK 用两个 `K=H64` 的 CG2 pass 累加到同一个 TMEM slot。
3. P/dS 是唯一跨 CTA 的数值 payload：每 CTA、每 tile 各发送一个
   4 KiB P 块和一个 4 KiB dS 块。
4. dKV 按 CTA 的 D128 quarter 排他 drain，pair 内没有同址 atomic 争用。

V4 在这套数据面上叠加 V3/V4 的供给侧实现：

1. 两个 K_dQ round 在一次 indexed pass 中一起 gather。
2. 八个 Q/dO panel generation 用两级 round pipeline 和两个轮转 TMA
   completion barrier 做软件流水。
3. Q、dO stationary readiness 拆开，首个 S 只等 Q。
4. score gather 发布单调 `khot_seq`，K_dQ 等对应序号后再重读同一批 KV 行。
5. `h == rank` 的 Q/dO panel 从本 CTA stationary buffer 做一次 16 KiB
   local bulk copy；`h != rank` 的 panel 继续从 GMEM/L2 走 TMA。
6. S/dP 的 32 个 atom 按 4 个 D128 chunk 组织，chunk 内使用 runtime
   `cutlass.range(..., unroll=4)`，避免 fully-unrolled issue body 膨胀。

## 1. 演进依据与当前性能状态

Baseline 的事实与测量口径仍由
[`Baseline设计文档.md`](Baseline设计文档.md) 维护。V2 针对 baseline
的主要结构攻击仍成立：减半 dKV atomic、消除 pair 内同址争用、让 S/dP
以 CG2 M128 运行、提前回收 score K stage。

从 V2 到 V3 的 native IKET 证据显示，tensor-core issue 侧已经优于
baseline，但 round-region operand supply 成为主墙：

```text
MAT_QDO ≈ 15.6 us/tile
ROUTE_K ≈ 5.6 us/tile
tile period ≈ 11.5 us（baseline ≈ 4.6 us）
```

V3 通过 depth-2 panel supply、fused K_dQ gather 和 split stationary
readiness 将整 kernel 降到 14.28 ms，但仍约为 baseline latency 的 1.77x。
V4 针对剩余三个已观察到的 pacer：

- leader S/dP issue：旧 fully-unrolled 形式约 73 ns/atom，baseline 约
  22 ns/atom；
- K_dQ 在 score gather 之前抢读 cold KV line；
- `h == rank` 的 resident Q/dO panel 仍被拆成 64-row TMA box。

V4 当前只完成了实现侧修正。它是否优于 V3、是否优于 same-run baseline，
都不是本文可预设的结论。

## 2. 约束与硬规则

**RMW 不可消除**：dKV 行由每 token 的 topk 索引散射，跨 token 冲突不可
避免；没有倒排索引就不能做 KV-stationary 零 atomic。当前实现只做
`减半 + pair 内去争用 + 与 GEMM 重叠`。

**P/dS 交换下界**：CG2 dV/dK 的 B 操作数按 N32 在 CTA 间拆分，而
softmax 结果按 H64 在 CTA 间拆分。每个 tile 至少需要交换：

```text
2 CTA × (P 4 KiB + dS 4 KiB) = 16 KiB
```

V4 恰好达到该下界。

实现硬规则：

- 不原位改写 stationary Q/dO；
- 不做跨维度 route 或片上 transpose；
- 每个 round buffer 同时只有一个 producer 和一个 leader consumer；
- follower CTA 的 W16 不参与任何 leader pipeline 操作；
- raw TMA completion barrier 在前一代完成前不得 re-arm；
- rows-hot 不使用奇偶 phase，因为 producer 可以领先 consumer 两代以上。

## 3. Kernel 边界与固定问题形状

构造函数强制：

```text
head_dim   = 512
head_dim_v = 512
block_tile = 64
element    = BF16
accumulator= FP32
```

主 kernel 的 grid 为 `(2 * query_tokens, 1, batch)`，两个相邻 block 组成
`(2,1,1)` cluster。每个 cluster 反向遍历
`tile_count = ceil(clamp(topk, 0, max_topk) / 64)` 个稀疏 tile。

整个 API 不是单次 launch：`__call__` 先运行 `sum_OdO`/scaled-LSE
预处理，再运行 V4 main kernel，随后运行 `convert_canonical` 和
`sum_dSink`。本文所说的 “fused” 仅指 main kernel 内的
S/dP/dQ/dV/dK。

## 4. Ownership 与数据面

记：

```text
c          = CTA rank ∈ {0,1}
peer       = 1-c
H64_c      = heads [64c, 64c+64)
Dq(r,c)    = D[256r+128c, 256r+128c+128)
r          ∈ {0,1}
```

| 数据 | 每 CTA 的形状 / 大小 | 来源 | 生命周期与消费者 |
|---|---:|---|---|
| stationary Q | `[H64_c,D512]` BF16，64 KiB | token 级 TMA | 整个 main kernel；S 与 own-half dK bulk 源 |
| stationary dO | `[H64_c,D512]` BF16，64 KiB | token 级 TMA | 整个 main kernel；dP 与 own-half dV bulk 源 |
| score K stage | `[N32_c,D512]` BF16，32 KiB | W0–3 sparse cp.async gather | 单级 `pipe_kscore`；S/dP 完成后回收 |
| round A/B | 各 16 KiB | fused K_dQ gather、local bulk 或 peer-half TMA | 两级 `pipe_round`，承载 10 generations/tile |
| P blocks | 两个 4 KiB block | math stmatrix；其中一个由 peer bulk 写入 | dV 的两个 H64 pass |
| P xchg | 4 KiB | math stmatrix | 单次 bulk DSM 的发送 staging |
| dS image | `[H64_c,N64]` BF16，8 KiB | math stmatrix | dQ 的本地 B operand |
| dS blocks | 两个 4 KiB block | math stmatrix；其中一个由 peer bulk 写入 | dK 的两个 H64 pass |
| dS xchg | 4 KiB | math stmatrix | 单次 bulk DSM 的发送 staging |
| softmax stats | `[H64_c,2]` FP32，512 B | scaled LSE、sumOdO cp.async | 整 token |
| `khot_seq` | 单调 CTA-shared sequence | score gather W0 | W17 的 K_dQ rows-hot gate |

与 V2 规格的两个重要区别：

- V4 没有 shared `sTopkIdx`；score gather、K_dQ gather 和 dKV drain
  各自读取 topk index，后两者依赖 cache locality。
- score K stage 没有在尾部 alias 为 dQ epilogue staging；dQ 当前直接
  T2R 后做标量 BF16 global store。

## 5. 五类 GEMM

实际参与 main math 的 MMA 全是 `CtaGroup.TWO`。host 侧另建的 CG1
`stationary_tiled_mma` 只用于生成 stationary TMA layout，不发出 GEMM。

| GEMM | Cluster 逻辑 `(M,N,K)` | A | B | TMEM |
|---|---|---|---|---|
| S | `(H128,N64,D512)` | CTA c 的 stationary Q `[H64_c,D512]` | CTA c 的 score K `[N32_c,D512]` | `t_score` |
| dP | 同 S | stationary dO | 同一 score K stage | `t_dp` |
| dQ r | `(D256,H128,N64)` | K_dQ `[N64,Dq(r,c)]` 的 MN-major image | 本 CTA 的完整 dS image `[H64_c,N64]` | `t_dq[r]`，跨 tile 累加 |
| dV(r,h) | `(D256,N64,H64)` | dO panel `[H64_h,Dq(r,c)]` | P block `[H64_h,N32_c]` | `t_dkv[r]` |
| dK(r,h) | `(D256,N64,H64)` | Q panel `[H64_h,Dq(r,c)]` | dS block `[H64_h,N32_c]` | 同一 `t_dkv[r]` |

每个 dKV round 的累计顺序固定为：

```text
dV(h0, acc=False)
dV(h1, acc=True)
dK(h0, acc=True)
dK(h1, acc=True)
```

两个 D256 round 使用两个独立 dKV TMEM slot。每 tile 都从
`dV(h0, acc=False)` 开始覆盖该 slot；reduce warps 在下一次复用前完成
T2R 并释放。

## 6. Round region：两级统一供给流水

每 tile 固定 10 个 generation：

```text
g0  K_dQ r0       -> dQ(r0)
g1  K_dQ r1       -> dQ(r1)
g2  dO[h0,r0]     -> dV(r0,h0)
g3  dO[h1,r0]     -> dV(r0,h1)
g4  Q [h0,r0]     -> dK(r0,h0)
g5  Q [h1,r0]     -> dK(r0,h1)
g6  dO[h0,r1]     -> dV(r1,h0)
g7  dO[h1,r1]     -> dV(r1,h1)
g8  Q [h0,r1]     -> dK(r1,h0)
g9  Q [h1,r1]     -> dK(r1,h1)
```

`pipe_round` 只有 A/B 两个 stage，full/empty 共四个 pipeline mbarrier。
它不是 V2 文档中“每个 generation 类型各一套 barrier”的实现。

g0/g1 的实现：

1. W17 连续 acquire 两个 stage credit；
2. 一次 `_fill_kdq_pair_v2` 遍历 N64，每行只读一次 index；
3. 同时把两个 D128 quarter 写进 A/B；
4. cp.async 完成后连续 commit 两个 generation。

g2–g9 的实现：

1. issue generation `q` 的 TMA 或 local bulk；
2. 从 `q>0` 开始 wait generation `q-1` 对应的 raw completion barrier；
3. wait 完立即 commit `q-1` 给 `pipe_round`；
4. 循环结束后再 wait/commit 最后一个 generation。

raw completion 只有两个 barrier，按 `h_half`/A-B 轮转。该顺序保证同一
barrier 上一次传输完成后才被重新设置 expected bytes。

## 7. V4 rows-hot 单调序列

score gather 与 K_dQ gather 读取相同的稀疏 KV 行，但切片方式不同。V4
让 K_dQ 在对应 score gather 完成后再发起：

```text
W0-3:
  sparse gather score K -> cp.async wait
  gather_barrier(128 threads)
  W0 release-store khot_seq = loop_iter + 1

W17:
  acquire-load/spin until khot_seq >= loop_iter + 1
  fused gather K_dQ r0+r1
```

这里必须是单调 sequence，而不是 count-1 mbarrier parity。score producer
可以合法地领先 W17 两个或更多 tile；phase bit 会发生 ABA 式别名并在
variable-length case 中死锁。`st.release.cta.shared.u32` 与
`ld.acquire.cta.shared.u32` 保证发布顺序，`>= target` 允许任意 producer
lead。

rows-hot 是 locality hint 加正确的代际同步，不改变数值依赖：score K 和
K_dQ 仍各自写独立 SMEM buffer。

## 8. V4 own-half bulk / peer-half TMA

`OWN_HALF_BULK=True` 时，八个 Q/dO panel 中：

- `h_half == rank`：源数据已经在本 CTA 的 stationary Q/dO；W17 从
  byte-identical 的 16 KiB 连续切片向 round A/B 做一次 local
  `cp.async.bulk`，目的 rank 仍是本 CTA；
- `h_half != rank`：本 CTA 没有对应 head half，继续从 GMEM/L2 用
  16 KiB TMA 填充。

每 CTA、每 tile 因此有四次 16 KiB local bulk 和四次 16 KiB TMA。
`OWN_HALF_BULK=False` 是编译期 fallback，八个 panel 全部走 TMA。

当前实现对四类 own-half 偏移使用：

```text
dO/Q round 0, rank 0:  0 KiB
dO/Q round 0, rank 1: 16 KiB
dO/Q round 1, rank 0: 32 KiB
dO/Q round 1, rank 1: 48 KiB
```

每个偏移指向 stationary K-major image 中一个 16 KiB、与 dKV A
MN-major stage 逐字节相同的 M-atom pair。该 byte identity 是启用
own-half path 的正确性前提。

## 9. P/dS 发布与 DSM 交换

math warps 对每个 tile 执行：

1. 等 S 与 dP completion，T2R 到寄存器；
2. 用 scaled LSE、sumOdO 计算 BF16 P 和 dS；
3. `pipe_pds.producer_acquire`，确保上一 tile 的本地 block、xchg 和 peer
   landing 已可覆写；
4. stmatrix 写本地 P/dS block、P/dS xchg，同时另写完整 `dS image`；
5. 128-thread math barrier；
6. W4 的 elected thread 各发一条 4 KiB P 和 dS bulk DSM 到 peer；
7. 再做一次 math barrier，随后 commit `pipe_pds`。

peer 的 bulk 直接落到 `p_blocks`/`ds_blocks` 中属于发送方 head half 的
最终位置，不再有额外 reorder。W18 relay warp 等待 P、dS 两个 landing
complete_tx，再分别 arrive 到 leader 可等待的 `relay_mbars`。

leader 在开始 dV/dK 前同时满足：

- `pipe_pds.consumer_wait`：本地 math image 与发送动作已发布；
- 两个 `relay_mbars`：peer P/dS payload 已落地。

leader 在 round 1 的 dV/dK 全部 issue 后 release `pipe_pds`，然后翻转
landing phase。该 release 是下一 tile producer 覆写 block/xchg 的唯一
许可。

## 10. 旋转调度

leader CTA 的 W16 是唯一 MMA issuer。稳态 iteration `t` 的实际顺序为：

```text
wait score K(t)
S(t)

if t > 0:
  wait P/dS(t-1)
  dQ(t-1,r0), dQ(t-1,r1)
  wait peer P/dS landing(t-1)
  dV/dK(t-1,r0)

if t == 0:
  wait stationary dO ready
dP(t)
release score K(t)

if t > 0:
  dV/dK(t-1,r1)
  release P/dS(t-1)
```

循环结束后单独 drain 最后一个 tile 的 dQ 和两个 dKV round，并发布一次
`dq_done`。这与旧 V2 文档里的示意顺序不同：当前实现把前一 tile 的两个
dQ round 放在 round-0 dV/dK 之前，而不是放在其后。

stationary readiness 被拆成两个 CTA-local signal：

- Q TMA 完成即可启动首个 S；
- dO TMA 只在首个 dP 前等待。

S/dP issue 本身按四个 D128 chunk 运行；每个 chunk 的 K atom loop 是
runtime range、`unroll=4`。这保留 baseline 已验证的 issue 形态，同时避免
32-atom fully-unrolled Python/DSL body。

## 11. Warp 角色与寄存器配置

V4 每 CTA 640 threads：

```text
W0-3    score K sparse gather；发布 khot_seq
W4-7    math：stats、S/dP T2R、P/dS、DSM sender、dQ epilogue
W8-15   reduce：两个 dKV slot 的 T2R + FP32x4 global atomic
W16     MMA leader；follower CTA 的 W16 不执行 pipeline 操作
W17     stationary TMA、fused K_dQ gather、八个 panel fill
W18     P/dS landing relay
W19     idle
```

当前可执行代码的 `setmaxnreg` 配置是：

```text
W0-3、W16-19 : decrease(48)
W4-15        : increase(128)
```

因此，旧注释中“issue warpgroup 提升到 80 registers”不是当前实现事实；
本文不采用该说法。

## 12. 资源预算

SMEM 字段按当前固定元素数和 1 KiB alignment 计算：

```text
stationary Q + dO                    131072 B
score K stage                         32768 B
round A + B                           32768 B
P blocks + P xchg                     12288 B
dS image + dS blocks + dS xchg        20480 B
softmax stats                            512 B
control/barrier 字段 + 首个 1KiB 对齐    1024 B
struct 尾部对齐                           512 B
------------------------------------------------
SharedStorageV2                      231424 B
硬上限                              232448 B
slack                                  1024 B
```

代码在 specialization 时执行
`SharedStorageV2.size_in_bytes() <= 232_448`，实际 launch 使用该编译期
size。

TMEM 固定 512 columns，无 alias：

```text
S      @   0,  64 col
dP     @  64,  64 col
dQ r0  @ 128, 128 col
dQ r1  @ 256, 128 col
dKV r0 @ 384,  64 col
dKV r1 @ 448,  64 col
```

## 13. 每 tile 的主要流量（每个 2-CTA cluster）

```text
score K sparse gather      64 KiB GMEM -> SMEM
K_dQ fused gather          64 KiB KV re-read（rows-hot 后，目标是 L2 hit）
Q/dO peer-half panels     128 KiB TMA/L2
Q/dO own-half panels      128 KiB SMEM local bulk
P/dS cross-CTA exchange    16 KiB DSM（理论下界）
dKV atomic value payload  128 KiB FP32 add
                           = 32768 scalar adds / tile / cluster
```

此外，每 token/cluster 一次性加载 stationary Q+dO 共 256 KiB，并在尾部
直接写出 dQ 共 128 KiB BF16。atomic 的真实 fabric/RMW 流量高于 value
payload；表中 128 KiB 只表示参与 add 的 FP32 数据量。

V4 相比全 TMA panel 路线，把 cluster 每 tile 的 Q/dO panel GMEM/L2
重读从 256 KiB 降到 128 KiB，另一半改为片上 local bulk。当前仍是
CONFIG R：T2R 后使用 `red.global.add.v4.f32`；V2 文档中的
`cp.reduce.async.bulk` CONFIG B 未在 V4 中实现。

## 14. 尾部与正确性协议

- **初始化**：所有 pipeline/raw mbarrier 与 `khot_seq=0` 在 producer
  活动前初始化；CTA barrier 后执行 cluster pipeline init。
- **遍历**：tile 按 `tile_count-1 ... 0` 逆序处理。dQ 的第一个实际 tile
  使用 `accumulate=False`，后续 tile 使用 `True`。
- **partial tile**：score K 与两个 K_dQ round 的无效行都显式写零；
  index `<0` 也按无效行处理。
- **P/dS mask**：实现不额外 mask 无效列。零填充使 S=dP=0 且 P/dS
  有限；dQ 由零 K_dQ 行保护；dKV 垃圾列由 drain 的
  `global_n < topk && kv_index >= 0` 丢弃。
- **dKV**：每 CTA 只写自己的 D128 quarter；两个 H64 pass 在 TMEM 中
  累加后，8 个 reduce warps 重建连续 FP32x4 并做向量 atomic。
- **lengths**：每 token 的 topk 被 clamp 到合法范围。rows-hot 用单调
  sequence，允许 score gather 任意领先 W17，不再有 parity alias。
- **T=0**：不加载 stationary、不进入 tile loop；math warps 直接把两个
  rank-owned dQ round 写零。
- **dQ 尾部**：当前 `_store_dq_from_tmem` 直接 T2R、转换 BF16、逐元素
  写 GMEM；host 虽构造 dQ TMA epilogue 对象，V4 main kernel 未使用它。
- **退出**：所有 warp relinquish TMEM permit，640-thread CTA barrier 后
  两 CTA 无条件 `cluster_arrive/wait`，最后释放 TMEM。

## 16. V2 规格到 V4 实现的差异表

| 项目 | V2 文档 | V4 实现 |
|---|---|---|
| threads/CTA | 512 / 16 warps | 640 / 20 warps |
| reduce warps | 4 | 8 |
| round supply | 10 generation 顺序模型 | 同顺序，实际为 2-stage unified pipeline |
| raw round barriers | 每类 generation 独立 | 两个 TMA completion barrier 轮转 |
| K_dQ | 两 round 分别 gather | 一次 pass 同时填 r0/r1 |
| stationary ready | Q/dO 合并描述 | Q 与 dO 分离 |
| K_dQ locality | 无显式 gate | `khot_seq` release/acquire gate |
| Q/dO panel | 八个 panel 全 TMA | 四个 own-half local bulk + 四个 peer-half TMA / CTA |
| P storage | 12 KiB | 12 KiB |
| dS storage | 12 KiB | 20 KiB（额外完整 dS image） |
| topk cache | shared `sTopkIdx` | 无；按角色重读 |
| dQ epilogue | K stage alias + TMA 目标 | 直接 T2R + 标量 BF16 store |
| dKV drain | CONFIG R/B | 仅 CONFIG R |
| S/dP issue | 未固定 lowering 形态 | chunk constexpr + inner runtime unroll-4 |
| rows-hot 同步 | 无 | 单调 shared sequence；禁止 parity mbarrier |
| register 计划 | 40/128-reg 估算 | 实码为 48 或 128 |

## 17. 验收

- **CP0 编译资源**：`SharedStorageV2 <= 232448 B`、TMEM=512、block=640；
  PTXAS spill/local=0；main S/dP/dQ/dV/dK 不出现 `.cta_group::1` MMA。
- **CP1 正确性/活性**：dense、lengths、holes、all-empty、partial N64、
  repeated index、`T∈{0,1,2,3,31,32}`；atol=rtol=5e-2；无超时或死锁。
- **CP2 V4 特有检查**：
  - producer 可领先至少三个 tile 时，`khot_seq` 仍能推进；
  - `OWN_HALF_BULK=True/False` 数值一致；
  - 四个 stationary slice 与 round A layout 做 byte-identity 校验；
  - IKET 中 K_dQ 位于对应 `LOAD_K` 发布之后；
  - g2–g9 不出现 completion barrier 提前 re-arm。
- **CP3 IKET/流量**：每 tile/cluster score K=64 KiB、K_dQ=64 KiB、
  peer-half TMA=128 KiB、own-half bulk=128 KiB、DSM=16 KiB、
  dKV scalar atomic=32768。
- **CP4 性能**：`latency_v4 < latency_v3` 是本轮改动的局部目标；
  `latency_v4 < same-run latency_baseline` 仍是唯一最终性能合同。
  在正式 B200 release + trace 验证完成前，不宣称 V4 达成任一目标。
